# Poke-Controller — Web 操作コンソール（設計プロトタイプ）

既存 tkinter 画面の移植ではなく、実装済みの機能を「ブラウザで操作するコンソール」として
情報設計から作り直したもの。バックエンドは持たず、映像・ログ・入力はモックで動く。

```
python -m http.server 8787 --directory webui
# http://127.0.0.1:8787/
```

- `index.html` / `styles.css` / `app.js` の3ファイル。ビルド不要。
- `?pad=1` でコントローラだけのウィンドウ（`window.open` のポップアウト先）。
- `#run` `#history` `#devices` `#diag` で画面を直接開ける。

## 何を変えたか（既存レイアウトとの違い）

| 既存 | この設計 |
|---|---|
| 設定タブ（シリアル / コントローラ / カメラ / オーディオ / コマンド / 履歴）が主領域を占める | 設定は「機器」という行き先へ。主領域は常に映像 |
| 常時見たい情報がタイトル・下端ステータス行・各タブに散る | 上端の状態帯に集約（接続・実行・映像・音声・問題件数・プロファイル） |
| 仮想コントローラがタブ内／別ウィンドウ | ステージ右の浮遊パネル。ドラッグ可・折りたたみ可・別ウィンドウ化可 |
| ログが設定タブの隣 | 下段ドック。ログ / 入力 / 通信の3ストリーム、水準・検索・追従・新着 |
| コマンド一覧が常設の欄 | 実行ビューの検索付き一覧＋全体パレット（Ctrl+K） |
| 画面モード（standard / compact / preview） | レスポンシブ。狭い幅ではサイドバーがドロワー、パッドが下シート |

## 情報の階層（ISA-101 の4レベルに対応）

- **L1 常時**（状態帯）: プロファイル、通信方式・ポート・baud、実行状態と経過、映像の解像度/fps/遅延、音声レベル、警告・エラー件数。
- **L2 作業**（ステージ＋文脈パネル）: 映像、入力ミラー、実行中のコマンド、コマンド一覧、履歴。
- **L3 詳細**（モーダル）: コマンドの入力、キーコンフィグ、表示フィルタ、HidHide、BCON の操作。
- **L4 診断**（診断ビュー＋通信ログ）: phase、送受信数、滞留、シリアルモニタ、エラー報告。

映像は行き先を切り替えても消えない。ログは常に下段にいる。この2つが「作業中に
見失ってはいけない面」で、設定は一度決めたら触らないので行き先の奥に置いた。

## 根拠にした資料

`~/research/pokecon-web-ui/`（imozuru の map / 原文 / 抜き書き `report.html`）に保存。

- PiKVM（KVM-over-IP の Web UI）: 1080p60 を 35–50 ms で出すには WebRTC H.264 が既定。MJPEG は帯域を食う。→ 映像を主面にし、方式は選べるが既定は低遅延側。
- ISA-101 / 高効率 HMI: 表示階層は4段まで、全体概要と作業詳細を分ける。→ 状態帯 / 文脈パネル / モーダル / 診断。
- VS Code の UI: Status Bar・Panel・Primary/Secondary Side Bar という語彙。→ 状態帯・下段ドック・行き先レール。
- Grafana の Live tail: 新着行に背景色、Pause / Resume / Clear を分ける。→ 追従 ON/OFF と「新着 N 行」。
- MDN Pointer events: pointer capture で要素外へドラッグしても入力を保持。→ スティックのドラッグ。
- NOOV「Nintendo Switchをブラウザから操作する」: 複雑なコマンド作成にブラウザのパッドは向かない。→ パッドは手動入力用、複雑な手順は Blockly（別タブ）へ。

## 状態と操作

- 接続: 接続 / 切断。未接続で実行すると理由つきで拒否。
- 実行: 待機 → 実行中（経過・手順・入力数・進捗）→ 一時停止 → 完了 / 停止。履歴に1行追加。
- ログ: 水準チップ、検索ハイライト、追従 ON/OFF、新着 N 行、問題だけ表示、コピー、消去。
- 入力: マウス（pointer capture）、キーボード（←↑↓→ / Z X A S / Q E / 1 3 / Enter Backspace）、Gamepad API、ポップアウトしたパッド（`postMessage`）。
- 映像: 保存（PNG ダウンロード）、範囲切り抜き（ドラッグ→PNG）、静止。
- キーボード: `Ctrl+Enter` 実行/停止、`Ctrl+Space` 一時停止、`Ctrl+K` パレット、`Esc` 停止/閉じる。

## 実装する場合のバックエンド契約（案）

- 映像: `GET /stream`（MJPEG）または WebRTC シグナリング。`GET /snapshot`。
- 状態: `WS /ws` で `state` / `log` / `input` / `wire` / `run` / `audio` を配信。ログは SSE でも可（単方向）。
- 操作: `POST /api/run` `{name}`、`/api/stop`、`/api/pause`、`/api/input` `{button,down}`、`/api/stick` `{side,x,y}`、`/api/capture`、`/api/crop`。
- 一覧: `GET /api/commands`、`GET /api/history`、`GET /api/profiles`。
- 既存の `CommandRunner` / `SerialService` / `AudioService` は tkinter 非依存なので、そのままプロセスの内側に置ける。

## 見た目

- 1アクセント（青）。状態色は緑=正常、橙=警告、赤=エラー/記録のみ。
- 角丸は 6 / 10 / 14 の3段。影は浮遊パネルとダイアログだけ。
- 数値は tabular-nums。ログ・通信・座標は等幅。
- 絵文字は使わず、インライン SVG の線アイコン。

## 検証したこと

`webui/shots/` のスクリーンショットは実ブラウザ（Chromium 1440×900 / 390×844）で撮影。

- 起動・ログ初期化・映像描画（60 fps 表示、モック）
- 実行 → 一時停止 → 再開 → 停止 → 履歴追加
- パッド押下（オーバーレイ・ミラー・入力ログ・通信ログ）
- スティックのドラッグとキーボード操作（矢印）
- ログ検索、水準フィルタ、問題のみ、追従、新着
- パレット（Ctrl+K）でのコマンド実行・画面移動
- 通信方式の切替（BCON カードの出現、baud 1 Mbps）
- 接続/切断と未接続時の実行拒否
- レスポンシブ（390×844、サイドバーのドロワー、パッドの下シート）
- パッドのポップアウト先（`?pad=1`）の描画

未検証: 実ハードウェア、実カメラ、実シリアル、実音声。モックデータのみ。
Blockly エディタ、スクリプト導入、ランチャーはこのプロトタイプの範囲外。
