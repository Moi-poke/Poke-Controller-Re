# BCON通信（接続・設定・計測）

## 前提

`bcon` は Pico 2 W 用のバイナリ通信方式である。テキスト行を送る従来方式と違い、姿勢を STATE バイナリに組んで送り、応答の STATUS / PONG / ACK を読み取る。Pico 側と版を合わせる必要があり、接続には `HELLO` による握手が必須である。既定 baud は 1Mbps であり、Pico 側は認証後に BCBR へ永続保存する。

接続先の相手に応じて使い分ける。本家 Leonardo には `legacy_text`、`switch-bcon` ファームを載せた Pico 2 W には `switch-bcon` を使う（標準は別プロセス `BconProcTransport`。同一プロセス版の内部テスト／開発用途は `switch-bcon-inproc`）。旧名 `bcon`・`switch-bcon-proc` も互換別名として `switch-bcon` へ解決する。

## 接続方式の選択と接続

通信方式は `register_transport` の登録簿で管理する。組み込みプリセットは `legacy_text` と `switch-bcon` の 2 件であり、内部・互換用に `switch-bcon-inproc` と別名 `bcon` / `switch-bcon-proc` を持つ。「シリアル」タブの「通信方式」には表示名（マイコン直結（USB シリアル）、Pico 中継（USB）など）が並び、表に無い方式は登録キーをそのまま出す（候補から落とさない）。内部キーは保存・比較に使い、方式の説明は「通信の詳細設定」を開くと読める。プラグインで登録した方式も候補に加わる。

### 利用者が通信方式を足す（v4 の manifest 方式）

`settings.ini` の `[Transport] plugin_dir` に置いたフォルダを参照する。1 方式につき 1 ディレクトリ構成とし、`manifest.toml` と `__init__.py` を置く。

```
plugin_dir/
  switch-pro-cont/
    manifest.toml
    __init__.py
```

```toml
name            = "switch-pro-cont"
version         = "1.2.0"
api_version     = 1          # 受け口の版。合わなければ読まない
min_app_version = "4.0.0"    # これ未満のアプリでは読まない
```

```python
# __init__.py
from Commands.Transport import Transport, register_transport


class SwitchProCont(Transport):
    name = "switch-pro-cont"


def register(register_transport):
    register_transport(SwitchProCont.name, SwitchProCont)
```

読み込まなかったときは、その理由（`manifest.toml` が無い・`api_version` が違う・`min_app_version` が新しい・import か `register` が失敗した）をログと画面に出す。1 本が壊れても他の方式は読み込む。`api_version` は `pokecon/plugins/transports.py` の `API_VERSION` が正本であり、破壊的変更のときだけ上げる。

`switch-bcon` の標準実装は別プロセス版（`BconProcTransport`）であり、120Hz 送出・受信・会話 op を子プロセスで回して GUI の GIL・描画負荷から切り離すことで、送出タイミングのばらつき（p99）を小さくする（旧名 `switch-bcon-proc` もこの別名として統一されている）。子プロセスが停止した呼び出しは安全既定値（`False` / `None`）を返し、開き直しで復帰する。同一プロセス版は `switch-bcon-inproc`（`BconTransport`）である。

起動時の優先順位は `--transport` が最上位であり、次が設定ファイルの `[Transport] name` である。`--transport` を付けると、設定を書き換えずにその場限りで試せる。名前が空・未知のときは `legacy_text` に戻る。

「シリアル」タブは「主要操作 → 詳細」の順である。タブには通信方式、COM ポート、「一覧更新」、「接続」「切断」が並び、結果は「接続」の直下に出て、失敗理由・注意もその近くに出る。選択値・実際の値・実測速度・`HELLO` の要約は「接続診断」にまとめ、通信速度の変更は「通信の詳細設定」で行う。

COM ポートの横の「一覧更新」は一覧を再取得するだけで、接続・切断や `HELLO` は行わない。保存したポートが空または見つからない場合、別のポートに自動接続しない。保存したポートが一覧にある場合は起動時に自動接続を試みる。接続済みではボタンが「再接続」になる。シリアルタブと BCON タブは通知の到着順ではなく、サービスの現在の接続状態を表示する。

接続状態（状態・実際のポート・通信方式）や、送信先・手動入力・Pico↔Switch の状態はタブ内に常時表示せず、標準レイアウトの下端の状態バーに出す（どのタブを開いていても見える）。表示する項目は「表示(V) → 常時表示する項目」で選べ、`[Window] status_items` に保存される。縦に長い設定欄はマウスホイールでスクロールできる。

BCON は「ポート接続中」→「HELLO 確認中」→「接続済み」と進む。ポートを開くだけでは接続成功ではなく、対応する版の `HELLO_ACK` を確認してから `STATE` の live 送出を始める。`HELLO` が失敗すると入力送出は抑止されたままで、ポートが開いたままの場合もある。原因を確認し、開いていればシリアルタブの「速度を探す」（失敗時に基本表示へ出る）または BCON タブの「通信テスト・詳細ログ」にある「HELLO をやり直す」「速度を探す」を使う。閉じていればシリアルタブで接続する。失敗理由には取得できたエラーが表示される。レガシー方式は `HELLO` 対象外であり、切断すると古い接続表示は消える。

「通信速度」の表示・変更はシリアルタブの「通信の詳細設定」で行う。現在の値は「次回の接続」と「接続中」を分けて表示する。BCON の候補は `BAUD_TABLE` の 115200 / 460800 / 921600 / 1000000 / 2000000 bps であり、従来方式の速度とは別の `bcon_baud_index` を使う（4800 の警告はレガシー方式に限る）。未接続時の選択は次回接続に使う。接続中の変更は、実際の速度が確認されたときだけ画面と設定値に反映する。変更に失敗した場合は、元の速度で改めて `HELLO` を確認できたときだけ元の接続状態と速度に戻る。確認できなければ接続失敗・速度不明となるため、「速度を探す」で確認する。探索で確認した速度に対応する index も設定値に反映し、設定ファイルへの書き込みはアプリの通常終了時に行う。

`baud_hunt` は候補 rate ごとに、まず短い `HELLO` で確定済みかを見て、返らなければ `NEUTRAL` を 5ms 間隔で 0.7 秒流す（呼び水）。Pico は未確定のあいだ各 rate に 150ms ずつ留まり、同じ滞在中に有効 frame が 2 連続で届いたときだけ確定するため、`HELLO` の単発（0.5 秒毎）では永久に確定しない（2026-10-05 実機で 0/5）。実機確認には `tools/probes/bcon_hunt_probe.py`（BREAK → `baud_hunt` → STATUS）を使う。

低速で確定した場合は探索の送出抑止を解除してから、`BAUD_SET` で 1Mbps への引き上げを試す。
旧速度で ACK を受け、guard 後に双方の速度を切り替え、`HELLO` で採用を確認する。
成功時は 1Mbps を最終速度とし、次の探索で優先する。
失敗時は既存の復帰手順で元の速度に戻り、`HELLO` を再確認できた場合だけその速度で接続を続ける。
115200bps のみ通る変換器でも、元の速度を確認できれば接続できる。
1Mbps 未満の設定で新しく接続する場合も、この探索を通してから HELLO と live 送信を開始し、最終速度を接続ログに出す。
接続後の手動の速度変更と「HELLO をやり直す」は選択済みの速度を維持する。

## BCON 設定の使い方

BCON 系の通信方式を選ぶと、メイン画面の「シリアル」の隣に「BCON」タブが現れる。「接続」メニューの「BCON 設定」もこのタブを選ぶため、別窓は開かない。BCON 以外ではシリアルタブの通信方式を選ぶよう案内が出る。単独画面のタイトルは「BCON 設定」である。

通信方式を切り替えるとタブは破棄されず隠れ、ログと未送信の色の下書きを保持する。非表示中は画面の poll・購読・取込期限の予約が止まり、再表示時には現在の状態を表示する。保守やログが画面下に隠れる場合はスクロールする。

埋め込みタブは常に 1 列で、上から「状態 → 主要操作 → 折りたたみ」の順である。状態は「接続方式」「プレイヤーLED」「ジャイロ」「振動」「コントローラー種別」を項目名と値の 2 列で表示する。未接続は `—`、接続済みで未取得は `未確認`、イベント待ちは `未受信`、機能なしは `なし`、受信値を解釈できないときは `不明` と書く。HELLO・STATUS・実際の速度・ポートは「通信テスト・詳細ログ」の中に置く。

主要操作は「状態を更新」と「Switchへ再接続」である。その直下の 1 行に、押せない理由と復旧操作を同じ行で出す。未接続なら `未接続 [シリアルタブを開く]`、HELLO 失敗なら `HELLO 未確認 [HELLO をやり直す] [速度を探す]` と表示する。理由が空でも行の高さは確保し、下の折りたたみを動かさない。

詳細は「接続モード・ペアリング」「通信テスト・詳細ログ」「本体色」「キーボード入力（検証）」「保守（取り消せない操作）」の折りたたみにまとめ、初回は閉じる。開閉しても下書き・選択・ログは消えない。保守は最下部に配置して既定で閉じ、開閉状態は保存しない。別ウィンドウでは従来の 2 列を維持する。

通常の状態確認、PING、色、取込、保守などは `HELLO` 確認済みで、他の操作もコマンドも実行していないときに使える。開いたポートでの `HELLO` 失敗時は「通信テスト・詳細ログ」の「HELLO をやり直す」と「速度を探す」で復旧を試せる（これらは接続済みでも使える）。ポートを閉じている間は操作が無効になり、直接操作を求めた場合もシリアルタブで接続するよう案内する。

操作中は該当する欄や入力が無効になり、進行状況や理由がシリアル側と BCON 側のログに出る。操作が完了して接続済みになれば次の操作を行える。重なった操作は拒否され、画面は通信処理の完了待ちで固まらない。コマンド実行中は通信方式、ポート、速度、HELLO の再試行、探索、保守を変更できないため、先にコマンドを停止する。緊急の「切断」はコマンドの停止を要求してからポートを閉じる。未接続でも画像だけを使うオフラインコマンドは実行できる。

- **主要操作**: 「状態を更新」は `STATUS_REQ` を送り、`STATUS`・`PLAYER_INFO` と対応 FW の `CONTROLLER_INFO` で状態欄を更新する。「Switchへ再接続」は Switch がコントローラを受け付ける状態で Pico に再接続を要求する（PC 側の接続し直しではない）。通信の再試行は「通信テスト・詳細ログ」にまとめる。「HELLO をやり直す」は入力送出を止めて `HELLO` を再試行し、「疎通確認（PING）」は `PONG` の往復時間と SEQ を確認する。
- **無線ペアリング（無線モードのみ）**: Pico が無線モードで、Switch に接続していないことを確認し、「取込開始」を押す。取込時間は 1～60 秒（初期値 15 秒）で、時間内に Joy-Con の HOME を長押しする。PC と Pico の接続は維持する。期限は要求秒数に 5 秒の余白を加え、`PLAYER_INFO` の保存情報を確認できた場合に「取込を保存しました。」と表示する。確認できなければ保存未確認と表示する。切断やタブ非表示などで期限の表示は取り消される。「保存した入力を再生」は `PLAYER_INFO` で保存済みを確認できた場合に使える。保存を確認したら「Switchへ再接続」を押す。
- **動作モード（変更すると再起動）**: 「有線にする」「無線にする」、「Pro Con」「Joy-Con L」「Joy-Con R」で Switch への接続方式と種別を変更する。「現在の方式」は `STATUS` の値を確認する。操作の前に、再起動で COM ポートが外れることを表示する。変更後は約 0.5 秒で Pico が再起動し、画面に再起動待ちが出る。ポートが戻ったら「シリアルタブを開く（一覧更新）」→「接続」を手動で行う（自動再接続は行わない）。
  コントローラー種別は FW 0.16 以降の `CONTROLLER_INFO`（`0x24`、LEN=1、0=Pro Con / 1=Joy-Con L / 2=Joy-Con R）で確認する。これは `STATUS_REQ` と周期 STATUS に付随し、次回起動用の保存値ではなく、起動時に適用した種別を返す。旧 FW は `未対応（FW 0.16 以降）`、対応 FW で応答が無ければ `未確認` と表示する。変更ボタンの選択から現在値を推測しない。再起動待ち・切断・接続失敗では種別を消し、再接続後の応答で更新する。
  再起動後の UART 接続で HELLO が通らない場合は「速度を探す」を使う。Pico の速度探索中は HELLO の単発送信だけでは確定しないことがある。接続失敗中は種別を確定表示せず、探索後に取得した値で更新する。
- **保守（取り消せない操作）**: 最下部の折りたたみに置く。「BOOTSEL再起動」は確認後、ファームウェア書き込み用に再起動する。書き込み中は接続を繰り返さず、書き込み後に「一覧更新」→「接続」を行う。「ペア鍵を全削除」は Pico の Classic リンク鍵と保存ホスト（BCHO）を削除する。**取込（BCW1）は残る**（`0x33` は取込削除に対応しない）。確認後に実行し、Switch 側の登録解除も必要である。
- **コントローラ状態**: `PLAYER_INFO` のプレイヤー LED 4 灯、IMU と振動の状態を表示する。点灯は黄緑、取得済みの消灯は暗色で描き、未接続・未取得は枠線だけで表示する。
- **本体色（RRGGBB）**: 折りたたみの中の本体・本体2・左・右の 4 欄に色を入力し、「色を送る」で `COLOR_SET` を送る。これはプレイヤー LED の色ではない。不正な値は送らず注意を出し、色は再接続後に反映される。閉じても未送信の下書きは保持する。
- **通信テスト・詳細ログ**: 選択値・実際の値・実測速度・`HELLO` の要約、HELLO 再試行、PING、速度探索、操作の進行・結果・拒否理由を表示する。ログタブへ自動で切り替えず、定期的な STATUS を毎秒ログへ出し続けることもしない。

シリアルタブの Switch 接続方式は読み取り専用の要約であり、変更は BCON タブで行う。`STATUS` 未受信時の方式は不明である。3 秒以上更新がなければ最後の値に「更新停止」を添え、無線や切断、再接続とは推定しない。切断・失敗時は ACK、STATUS、LED、振動の表示を消す。

CONFIG の結果は操作前後の STATUS を比較して判断する。`errcode` は過去のエラーを保持する場合があり、前後で `errcode`・`err_drop`・`err_crc` が変わらなければ、残った `errcode` だけで今回の操作を拒否と判定しない。

### コントローラー種別の実機確認（2026-11-21）

Pico 2 W 1台に FW 0.16 を書き込み、FTDI のデータ UART（1Mbps）で確認した。`HELLO_ACK=04 00 10 00`、Pro Con / Joy-Con L / Joy-Con R の取得、設定後・再起動前は従来の種別を返し、再起動後は保存した種別へ変わることを確認した。同じ種別の再指定も即時応答し、再起動せず STATUS を取得できた。

標準の別プロセス版と同一プロセス版の実 Tk 画面で Pro Con の表示と「状態を更新」を確認した。別プロセス版では Pro Con → Joy-Con L → Pro Con の設定・再起動・再接続を通し、再起動待ちと HELLO 失敗中は `—`、速度探索で復旧後は実際の種別になることを確認した。探索途中に 115200bps からの引き上げに失敗した回は、その速度で HELLO を確認して接続が継続し、最後は 1Mbps に戻った。

この確認は PC に有線 USB 接続した Pico とデータ UART の通信・画面表示に限る。Switch 本体での種別認識、無線 USB-CDC、旧 FW 実機との互換性は未確認である。検証終了時は Pro Con・有線・1Mbps に戻した。

## キーボード入力（検証）

有線 USB キーボード対応ファーム（v0.13 以降）で、BCON タブの「キーボード入力（検証）」を開き、文字列を入力して「入力して送信」を押す。US 配列の ASCII に対応する。日本語・IME は未対応で、未対応文字が1文字でもあれば全文を送らず、その文字と位置をログに出す。無線モードではフレームを受理しても Switch に文字は届かない。
`HELLO_ACK` の FW minor が 13 未満なら送信を拒否し、書き込みを案内する。
13〜14 は送信できるが、FW15 未満はキーボード取りこぼし対策前と警告する。

「キーボード操作」が ON でも、入力欄にフォーカスがある間は、打鍵をコントローラ操作へ送らない。入力欄の外では通常のコントローラ操作が有効になるため、注意を表示する。文字入力の検証中は「キーボード操作」を OFF にすると確認しやすい。

各文字は押下 → 50ms 待機 → キー解放 → 50ms 待機の順で送る（既定で毎秒 10 文字）。
「間隔(ms)」で 20〜200ms を 10ms 刻みで選べる。送信開始時に値を読み、実行中は入力欄とともに無効にする。
間隔が100msを超える場合も、press保持中は **80ms周期**（`KEY_REFRESH_S`）で同じpress全状態を再送する。
これは spec §5.14 の「非中立の間は100ms以内で同じ全状態を再送」を満たすためで、UART/CDCのフレーム欠落も次周期で復帰する。
最後に全ゼロの neutral を指定間隔で 2 回送る。「キー解放」も同じ neutral を 2 回送る。
送信失敗、タブの非表示、窓の閉鎖、接続世代の変更で送信を中止したときも解放を試みる。切断済みや入力抑止中には送れないため、再接続後にキーが残っていれば「キー解放」を押す。

ログの文字数は通信への書き込みが成功した押下レポート数であり、Switch に入力された文字数ではない。
`switch-bcon`（`BconProcTransport`）でも子プロセスが送信処理を実行した結果を待つ。入力抑止や HELLO 未確認による子の拒否は成功に数えない。
Pico の受信と USB 出力は、この結果だけでは確認できない。実機ではファームの `kbr` / `kbd` と Switch の入力結果を確認する。

### API とフレーム

`BconTransport.send_keyboard(report: bytes) -> bool` は HID boot keyboard の8Bレポートを、`T_KEYBOARD=0x3C`、LEN=8 の1フレームで送る。payload は修飾キー1B、予約0の1B、HID Usage ID 6個の順。既存の STATE／IMU／会話フレームと SEQ を共有し、1回の `write()` で送る。HELLO は引き続き `PROTO_VER=4` を使い、ファーム minor 13 を受け付ける。

`BconProcTransport.send_keyboard` も同じ8Bを受け付け、既存の `call` RPC で子の `send_keyboard` を呼び、実行結果を返す。入力行のフックや入力ログ、STATE の最新姿勢には混ぜない。

`pokecon.domain.serial.bcon_keyboard` は `report(mod, key)`、`NEUTRAL`、`prepare_text(text)`、`send_text(send, text, interval_s=0.050, refresh_s=0.080)`、`release_keys(send, interval_s=0.050)` を提供する（`interval_s`/`refresh_s` はキーワード引数）。大文字と記号は US 配列の Shift を使い、`\n`／`\r` は Enter、`\b` は Backspace、`\t` は Tab、`\x1b` は Esc に写す。`send_text` は全文検証後に送信し、書き込めた文字数と失敗理由を返す。

## 計測と不具合対応

`tools/probes/bcon_jitter.py` は 120Hz 送出の揺らぎを量るツールである。ポートを開き、互換版 Pico と `HELLO` を確認してから、中立 `STATE` を 120Hz で送り、要約と CSV を出して閉じる。`HELLO` が失敗または例外になった場合は、送信ループを始めず、要約と CSV を出さずに非 0 で終了する。任意の秒数だけ中立を送り、送信間隔の分布と差分を見る。

引数は `--port` が必須であり、data-UART のポートを指す（例: `COM9`）。`--baud` は通信速度で既定が `1000000`、`--secs` は計測秒数で既定が `10.0` である。`--latency-note` は変換器設定の覚書であり、FTDI 既定 16ms が 120Hz の致命傷になるため、`FTDI timer=1ms` のような前後比較用メモを CSV 先頭へ残す。`--csv` は CSV の出力先で、未指定だと時刻つき自動名になる。互換版 Pico との `HELLO` が必須であり、Pico のない TX / RX loopback では `HELLO` 応答がないため、この `STATE` 計測や IMU 送信診断は実行できない。

出力は 1 行要約 `p50=X.XXms p99=Y.YYms sent=N seq_gap=M err_crc=+0 err_drop=+0` と `csv=...` である。`p50` と `p99` は送信間隔の百分位、`sent` は STATE 送出数、`seq_gap` は SEQ 欠番数、`err_crc` と `err_drop` は前後 STATUS 差分（符号つき、`+0` が正常）を示す。CSV は `idx`・`t_s`・`delta_ms` の 3 列であり、先頭の `#` 行に実行条件（`port`・`baud`・`secs`・`latency_note`・`no_hello=False`・`samples`）と要約行が残る。`#` 行つきのため、pandas では `comment='#'` で読み込む。

不具合時はログ文言を頼りに切り分ける。

- **HELLO 不通・版不一致**: 表示された理由と、Pico の版・配線・電源・通信速度を確認する。ポートが開いていれば「HELLO をやり直す」や「速度を探す」を使う。版が合わなければ入力送出は抑止される。
- **動作モードや種別の切替後**: 再起動を待ち、ポートが戻ってからシリアルタブの「一覧更新」→「接続」を行う。
- **STATUS 異常**: 「状態を更新」で直近の `flags`・`last_seq`・`err_crc`・`err_drop`・`errcode` を読み直す。`err_crc`・`err_drop` が増え続ける場合は配線と通信速度を確認する。`errcode` は過去の記録が残る場合もある。

## 制限・既知事項

- PC は ver=4 専用である。DOWNGRADED・UNSUPPORTED・版違いは NEUTRAL 維持で止まり、自動追従しない。
- TX を RX へ折り返した loopback では自 STATE が RX へ戻り SEQ 連続性（`seq_gap`）も見られる。診断ツールは互換版 Pico との `HELLO` を必須とするため、HELLO 応答のない loopback だけでは計測できない。
- 有線中の取込・BEACON 要求は `0x10` / `0x11` で拒否される。撮り直し・再生には**無線にする**＋再起動が必要である。
- 計測秒数 `secs` は 1.0 から 120.0 秒の範囲に丸める。中断時は「中断した。ここまでの分で集計する。」と出し、途中までの分で集計する。
- Windows では待ち粒度を 1ms へ上げて量る。既定 15.6ms のままでは 8.33ms 刻みが延び、計測値を壊す。
