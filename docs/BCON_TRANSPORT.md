# BCON通信（接続・設定・計測）

## 前提

`bcon` は Pico 2 W 用のバイナリ通信方式である。テキ
スト行を送る従来方式と違い、姿勢を STATE バイナリ
に組んで送り、応答の STATUS / PONG / ACK を読む。
Pico 側と版を合わせる必要があり、接続には `HELLO`
による握手が必須である。既定 baud は 1Mbps で、Pico
側は認証後に BCBR へ永続保存する。

相手で使い分ける。本家 Leonardo には `legacy_text`、
`switch-bcon` ファームを載せた Pico 2 W には `switch-bcon`
または `switch-bcon-proc` を使う。旧名 `bcon` も受け付ける。

## 接続方式の選択と接続

通信方式は `register_transport` の登録簿で管理する。
組み込みは `legacy_text`、`switch-bcon`、
`switch-bcon-proc` の 3 件である。「シリアル」タブの
「通信方式」には表示名（マイコン直結（USB シリアル）、Pico UART（旧方式）、
Pico 中継（USB）、Pico 中継（別プロセス））が並び、表に無い方式は
登録キーをそのまま出す（候補から落とさない）。内部キーは保存・比較に
使う。方式の説明は「通信の詳細設定」を開くと読める。
プラグインで登録した方式も候補に加わる。

`switch-bcon-proc` は送出路の別プロセス版である。操作面は
`switch-bcon` と同じで、120Hz送出・受信・会話opを子プロセス
で回し、GUIのGIL・描画負荷から切り離す。送出タイミングの
ばらつき（p99）が小さくなる。子が死んだ呼出しは安全既定値
（False/None）で返し、開き直しで復帰する。

起動時の優先順位は `--transport` が最上位で、次が設
定ファイルの `[Transport] name` である。`--transport`
を付けると設定を書き換えずにその場限りで試せる。名
前が空・未知のときは `legacy_text` に戻る。

「シリアル」タブは「主要操作 → 詳細」の順である。接続状態（状態・実際の
ポート・通信方式）はタブ内に常時表示せず、下端の状態バーに出す。タブには
通信方式、COM ポート、「一覧更新」、「接続」「切断」が並び、結果は
「接続」の直下に出る。失敗理由・注意もその近くに出す。選択値・実際の値・実測速度・`HELLO` の要約は
「診断・送信ログ」にまとめ、通信速度の変更は「通信の詳細設定」で行う。
COM ポートの横の「一覧更新」は一覧を再取得するだけで、接続・切断や
`HELLO` は行わない。保存したポートが空または見つからない場合、
別のポートに自動接続しない。保存したポートが一覧にある場合は
起動時に自動接続を試みる。接続済みではボタンが「再接続」になる。
シリアルタブと BCON タブは通知の到着順ではなく、サービスの現在の接続状態を表示する。
送信先、手動入力、Pico↔Switch の状態は、タブ内に常時表示せず、標準レイアウトの
下端の状態バーに出す（どのタブを開いていても見える）。表示する項目は
「表示(V) → 常時表示する項目」で選べ、`[Window] status_items` に保存される。
縦に長い設定欄はマウスホイールでスクロールできる。

BCON は「ポート接続中」→「HELLO 確認中」→「接続済み」と進む。
ポートを開くだけでは接続成功ではなく、対応する版の `HELLO_ACK` を
確認してから `STATE` の live 送出を始める。`HELLO` が失敗すると
入力送出は抑止されたままで、ポートが開いたままの場合もある。
原因を確認し、開いていればシリアルタブの「速度を探す」（失敗時に基本表示へ
出る）または BCON タブの「通信診断・詳細ログ」にある「HELLO をやり直す」
「速度を探す」を使う。閉じていればシリアルタブで接続する。
失敗理由には取得できたエラーが表示される。レガシー方式は `HELLO` 対象外である。
切断すると古い接続表示は消える。

「通信速度」の表示・変更はシリアルタブの「通信の詳細設定」で行う。
現在の値は「次回の接続」と「接続中」を分けて表示する。BCON の候補は
`BAUD_TABLE` の 115200 / 460800 / 921600 / 1000000 / 2000000 bps で、
従来方式の速度とは別の `bcon_baud_index` を使う。4800 の警告は
レガシー方式に限る。未接続時の選択は次回接続に使う。
接続中の変更は、実際の速度が確認されたときだけ画面と設定値に反映する。
変更に失敗した場合は元の速度で改めて `HELLO` を確認できたときだけ
元の接続状態と速度に戻る。確認できなければ接続失敗・速度不明となり、
「速度を探す」で確認する。探索で確認した速度に対応する index も
設定値に反映する。設定ファイルへの書き込みはアプリの通常終了時である。

`baud_hunt` は候補 rate ごとに、まず短い `HELLO` で確定済みかを
見て、返らなければ `NEUTRAL` を 5ms 間隔で 0.7 秒流す（呼び水）。
Pico は未確定のあいだ各 rate に 150ms ずつ留まり、同じ滞在中に
有効 frame が 2 連続で届いたときだけ確定するため、`HELLO` の単発
（0.5 秒毎）では永久に確定しない（2026-10-05 実機で 0/5）。
実機確認は `tools/bcon_hunt_probe.py`（BREAK→`baud_hunt`→STATUS）。

## BCON 設定の使い方

BCON 系の通信方式を選ぶと、メイン画面の「シリアル」の隣に
「BCON」タブが現れる。「接続」メニューの「BCON 設定」もこのタブを
選ぶ。別窓は開かない。BCON 以外ではシリアルタブの通信方式を
選ぶよう案内が出る。単独画面のタイトルは「BCON 設定」である。

通信方式を切り替えるとタブは破棄されず隠れ、ログと未送信の色の
下書きを保持する。非表示中は画面の poll・購読・取込期限の予約が止まり、
再表示時には現在の状態を表示する。保守やログが画面下に隠れる場合は
スクロールする。

タブは上から「状態 → 主要操作 → 詳細」の順である。状態は
「PC ↔ Pico」「Pico ↔ Switch」「現在のモード（接続方式・種別）」の 3 行で、
取得できない種別は「不明」と書く。主要操作は「状態を更新」と
「Switchへ再接続」で、結果はその直下に出る。接続に失敗している間は、
その下に「HELLO をやり直す」「速度を探す」も出る（詳細を開かなくても
復旧へ届く）。詳細は
「接続モード・ペアリング」「本体色（RRGGBB）」「通信診断・詳細ログ」
「保守（取り消せない操作）」の折りたたみにまとめ、初回は閉じる。
開閉しても下書き・選択・ログは消えない。幅が足りないときは 1 列、
広いときは操作列と状態・ログ列を左右に並べる。

通常の状態確認、PING、色、取込、保守などは `HELLO` 確認済みで、
他の操作もコマンドも実行していないときに使える。
開いたポートでの `HELLO` 失敗時は「通信診断・詳細ログ」の
「HELLO をやり直す」と「速度を探す」で復旧を試せる。これらは接続済みでも使える。
ポートを閉じている間は操作が無効になり、直接操作を求めた場合も
シリアルタブで接続するよう案内する。

操作中は該当する欄や入力が無効になり、進行状況や理由がシリアル側と
BCON 側のログに出る。操作が完了して接続済みになれば次の操作を行える。
重なった操作は拒否され、画面は通信処理の完了待ちで固まらない。
コマンド実行中は通信方式、ポート、速度、HELLO の再試行、探索、保守を
変更できないため、先にコマンドを停止する。緊急の「切断」はコマンドの
停止を要求してからポートを閉じる。未接続でも画像だけを使うオフライン
コマンドは実行できる。

- **操作**: 「状態を更新」は `STATUS_REQ` と `PLAYER_INFO` を読み、
  状態の 3 行を更新する。「Switchへ再接続」は Switch がコントローラを
  受け付ける状態で Pico に再接続を要求する（PC 側の接続し直しではない）。
  通信の再試行は「通信診断・詳細ログ」にまとめる。
  「HELLO をやり直す」は入力送出を止めて `HELLO` を再試行し、
  「疎通確認（PING）」は `PONG` の往復時間と SEQ を確認する。
- **無線ペアリング（無線モードのみ）**: Pico が無線モードで、Switch に
  接続していないことを確認し、「取込開始」を押す。取込時間は 1～60 秒
  （初期値 15 秒）で、時間内に Joy-Con の HOME を長押しする。
  PC と Pico の接続は維持する。期限は要求秒数に 5 秒の余白を加え、
  `PLAYER_INFO` の保存情報を確認できた場合に「取込を保存しました。」と
  表示する。確認できなければ保存未確認と表示する。切断やタブ非表示などで
  期限の表示は取り消される。「保存した入力を再生」は `PLAYER_INFO` で
  保存済みを確認できた場合に使える。保存を確認したら「Switchへ再接続」を押す。
- **動作モード（変更すると再起動）**: 「有線にする」「無線にする」、
  「Pro Con」「Joy-Con L」「Joy-Con R」で Switch への接続方式と種別を
  変更する。「現在の方式」は `STATUS` の値を確認する。操作の前に
  再起動で COM ポートが外れることを表示する。変更後は約 0.5 秒で
  Pico が再起動し、画面に再起動待ちが出る。ポートが戻ったら
  「シリアルタブで接続し直す」→「一覧更新」→「接続」を手動で行う。
  自動再接続は行わない。
- **保守（取り消せない操作）**: 最下部の折りたたみに置く。
  「BOOTSEL再起動」は確認後、
  ファームウェア書き込み用に再起動する。書き込み中は接続を繰り返さず、
  書き込み後に「一覧更新」→「接続」を行う。「取込を破棄」は取込と Classic 鍵を
  破棄し、「ペア鍵を全削除」は Pico のペア鍵をすべて削除する。
  どちらも確認後に実行し、Switch 側の登録解除も必要である。
- **コントローラ状態**: `PLAYER_INFO` のプレイヤー LED 4 灯、IMU と
  振動の状態を表示する。点灯は黄緑、消灯は灰色である。
- **本体色（RRGGBB）**: 折りたたみの中の本体・本体2・左・右の 4 欄に色を入力し、
  「色を送る」で `COLOR_SET` を送る。これはプレイヤー LED の色ではない。
  不正な値は送らず注意を出す。色は再接続後に反映される。閉じても
  未送信の下書きは保持する。
- **通信診断・詳細ログ**: 選択値・実際の値・実測速度・`HELLO` の要約、
  HELLO 再試行、PING、速度探索、操作の進行・結果・拒否理由を表示する。
  ログタブへ自動で切り替えず、定期的な STATUS を毎秒ログへ出し続けることもしない。

シリアルタブの Switch 接続方式は読み取り専用の要約で、変更は BCON タブで行う。
`STATUS` 未受信時の方式は不明である。3 秒以上更新がなければ最後の値に
「更新停止」を添え、無線や切断、再接続とは推定しない。切断・失敗時は
ACK、STATUS、LED、振動の表示を消す。

CONFIG の結果は操作前後の STATUS を比較して判断する。`errcode` は過去の
エラーを保持する場合があり、前後で `errcode`・`err_drop`・`err_crc` が
変わらなければ、残った `errcode` だけで今回の操作を拒否と判定しない。

## 計測と不具合対応

`tools/bcon_jitter.py` は 120Hz送出の揺らぎを量る道具だ。
ポートを開き、互換版 Pico と `HELLO` を確認してから、中立 `STATE` を
120Hz で送り、要約と CSV を出して閉じる。
`HELLO` が失敗または例外になった場合は、送信ループを始めず、要約と CSV を
出さずに非 0 で終了する。
任意の秒だけ中立を送り、送信間隔の分布と差分を見る。

引数は `--port` が必須で、data-UARTの口を指す(例
`COM9`)。`--baud` は速度で既定が `1000000`、`--secs`
は計測秒数で既定が `10.0` だ。`--latency-note` は変換器
設定の覚書で、FTDI既定16msが120Hzの致命傷になるため、
`FTDI timer=1ms` のような前後比較用メモをCSV先頭へ残す。
`--csv` はCSVの出先で、未指定だと時刻つき自動名になる。
互換版 Pico との `HELLO` が必須である。Pico のない TX/RX loopback では
`HELLO` 応答がないため、この `STATE` 計測や IMU 送信診断は実行できない。

出力は1行要約
`p50=X.XXms p99=Y.YYms sent=N seq_gap=M err_crc=+0 err_drop=+0`
と `csv=...` だ。`p50` と `p99` は送信間隔の百分位で、
`sent` はSTATE送出数、`seq_gap` はSEQ欠番数、`err_crc` と
`err_drop` は前後STATUS差分(符号つき、`+0` が正常)だ。CSV
は `idx`・`t_s`・`delta_ms` の3列で、先頭の `#` 行に実行
条件(`port`・`baud`・`secs`・`latency_note`・`no_hello=False`・
`samples`)と要約行が残る。`#` 行つきのためpandasでは
`comment='#'` で読む。

不具合時はログ文言を頼りに切り分ける。

- HELLO 不通・版不一致: 表示された理由と、Pico の版・配線・電源・
  通信速度を確認する。ポートが開いていれば「HELLO をやり直す」や
  「速度を探す」を使う。版が合わなければ入力送出は抑止される。
- 動作モードや種別の切替後: 再起動を待ち、ポートが戻ってから
  シリアルタブの「更新」→「接続」を行う。
- STATUS 異常: 「状態確認」で直近の `flags`・`last_seq`・`err_crc`・
  `err_drop`・`errcode` を読み直す。`err_crc`・`err_drop` が増え続ける
  場合は配線と通信速度を確認する。`errcode` は過去の記録が残る場合もある。

## 制限・既知事項

- PCはver=4専用だ。DOWNGRADED・UNSUPPORTED・版違いは
  NEUTRAL維持で止まり、自動追従しない。
- TXをRXへ折返したloopbackでは自STATEがRXへ戻りSEQ連続性
  (`seq_gap`)も見られる。診断ツールは互換版 Pico との `HELLO` を
  必須とするため、HELLO 応答のない loopback だけでは計測できない。
- 有線中の取込・BEACON要求は `0x10` / `0x11` で拒否される。
  撮り直し・再生は**無線にする**＋再起動が必要だ。
- 計測秒数 `secs` は1.0から120.0秒の範囲に丸める。中断時は
  「中断した。ここまでの分で集計する。」と出し、途中
  までの分で集計する。
- Windowsでは待ち粒度を1msへ上げて量る。既定15.6msのまま
  では8.33ms刻みが延び、計測値を壊す。
