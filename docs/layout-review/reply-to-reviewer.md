## 2. 高さ条件：「本文 666px」を撤回し、「パッド下端が見える」に変更

| パッド選択行 | 約 30 |
| 仮想コントローラ枠（見出し + パッド 202 + 余白） | 約 240 |

## 3. 自動切り替えの仕様（追加レビューの 4 点をすべて決める）

自動切り替えは `tabs_right` のときだけ。設定の `arrangement` と `show_log` は変更しない（**実効レイアウトだけ**を切り替える）。

| 項目 | 仕様 |
|---|---|
| 対象 | ユーザーの設定が `tabs_right` のときだけ。他の配置では何もしない。 |
| 幅の下限 | `right_min` は**論理pxで 415**（=ceil(420×0.9+36.8)）。物理は 100% 415 / 125% 519 / 150% 623（切り上げ）。`pad_req_logical = canvas.winfo_reqwidth() / factor`、`factor = winfo_fpixels("1i") / 96`（125%で1.25。**Tk scaling の1.666は1ptあたりpxなので使わない**）。1:1 は論理 457（物理 571 / 685）。実測の右列 523 物理は 91% で下限を満たす。 |
| 左列の下限 | **論理px**。`left_min = 380` を推奨（映像 380×214 論理）。480 にすると 1024×600@125%（819 論理）と 1280×720@150%（853 論理）が `right_min+480` を割り、`tabs_right` にできない。400 でも 1024@125 は sash 6px を引くと 399 論理で 1px 足りない。 |
| フォールバック開始 | **論理幅** `W_logical < right_min_logical + left_min + sash_logical`。`left_min=380`、`sash≈4.8`、`right_min≈415` の 125% で約 **800**（物理 1000）。**この値は実行時計算で、800 は例**。 |
| 復帰 | 上記の実行時しきい値 + **40 論理px**（125%で約 840 / 物理 1050）。 |
| 起動時 | ヒステリシスは使わず、`W_logical >= runtime_threshold` なら `tabs_right`、未満ならフォールバック。帯の中なら `tabs_right` で開始。 |
| デバウンス | 最後の `<Configure>` から **150ms** 待って判定。連続リサイズ中は組み替えない。 |
| DPI 変化 | 計測では `SetProcessDPIAware` を呼び、Tk scaling 1.666（=120dpi/72）の**システム DPI 対応**として動いている（GDI surface にも同じ呼び出しがある）。拡大率は `factor = winfo_fpixels("1i")/96`（125%で1.25）。システム DPI 対応ならモニタ移動で `winfo_fpixels` は変わらず、再計算不要。**per-monitor DPI の場合だけ** `WM_DPICHANGED` を受ける。実装時に `GetProcessDpiAwareness` で確認する。 |
| 保存しないもの | 実効配置、実効ログ表示、フォールバック時の仕切り位置。`arrangement` / `show_log` / `pane_sashes` は触らない。 |
| 仕切り位置の保護 | 一時切り替えで `PaneArranger` を組み直すとき、`remember_sashes` を**抑制**する。抑制しないと、フォールバック形の比率が保存済みの形を上書きする。 |
| ログの復元 | 自動で隠した場合だけ戻す。ユーザーが元々ログを隠していた場合は、その設定を維持する。 |
| 右列幅の保存 | **論理px**（物理px ÷ `factor`）。125% の 523px は 418 として保存し、復元時に ×1.25 する。 |
| 手で仕切りを動かした | 左列の上下仕切り: ドラッグ後は**ログの高さ `log_h` を論理pxで保存**し、自動のログ高さ計算を停止（仕切りの上端位置ではなく、ログの高さを保存する）。「仕切りを既定の位置に戻す」で解除。右列: `right_min` 未満へはドラッグ不可。 |
| 一時切り替え中 | 仕切りドラッグは無効化（または無視）。`remember_sashes` は抑制。 |
| 表示上の扱い | メニューは `tabs_right` を選択したまま。狭いため一時的にフォールバックしている旨を、状態バーかツールチップに出す（任意）。 |

### 実装上の注意

- 現在の `PaneArranger.remember_sashes()` は、配置を組み直すたびに比率を控える。自動切り替えで形が変わると、`log_right` の比率を上書きし得る。**一時切り替え中は控えない**フラグが必要。
- `show_log` を `setPaneVisible` で false にすると保存される。自動側は `arrangement_tree(..., show_log=False)` へ直接渡し、設定変数は触らない。
- 定数にしてよいのは `left_min`・ヒステリシス（40 論理px）・縮小率（0.9）だけ。`right_min` と `W_fallback` は実行時に `pad_req` と sash から計算する（800/840 は 125% の例）。

## 4. ログの高さ：「重み 4:1.5」ではなく、映像の必要高さから残りを回す

追加レビューの指摘どおり、重みで近似するより、**映像に必要な高さを計算して残りをログへ**回す方が崩れない。

### 計算

1. 左列幅 `left_w`（1280 で約 741、1920 で約 1390）
2. プレビュー内側 `preview_w = left_w - 14`
3. 16:9 の映像高 `video_h = preview_w × 9 / 16`
4. カメラ枠の必要高 `camera_h = video_h + 66（ツールバー等）+ 30（実行バー）`
5. `log_h = total_h - camera_h`。`log_h < 180` なら `log_h = 180`、`camera_h = total_h - 180`
6. 仕切りは `camera_h` の位置へ置く（比率ではなく px。DPI 変更時は再計算）

### 数値

| ウィンドウ | 左列幅 | 映像 | ログ | 備考 |
|---|---|---|---|---|
| 1280×720 | 741 | 727×409 | 約 179 → 180 | 映像は横幅で決まる |
| 1920×1080 | 1390 | **1365×768** | **180** | 先にログ最小 180 を確保。映像は 768 高で頭打ち |
| 2560×1080 | 2030 | 高さで頭打ち | 180（最小） | 映像が高さで決まる領域 |

数値は 125% の実測/計算。実装では `96`（ツールバー等）と `180`（ログ最小）を固定値にせず、ウィジェットの要求高から測る。

**訂正（前回の数値）:** 1920 で「映像 1376×774 とログ 180」は同時に成り立たない。必要な高さは 774+96+180=1050 で、使える 1044 を超える。正しくは、ログ 180 を先に引くとカメラ枠 864、映像の高さ 768、幅 1365。したがって 1920×1080 でも**わずかに高さで頭打ち**になる。

高さで頭打ちになる左列幅のしきい値は、固定の 1685px ではなく、式で決まる:

```
video_h_max = total_h - chrome(96) - log_min(180)
video_w_max = video_h_max * 16 / 9
left_w_threshold = video_w_max + 14
```

1920×1080（125%）では `(1044-96-180)=768`、`768*16/9=1365`、`+14=1379`。左列が 1379px を超えると高さで頭打ち。

それでも「映像の必要高さを計算し、残りをログへ」という規則は正しい。1920 ではログが最小 180px になり、1280 では約 180px になる。

## 6. 残る実測

- 100% / 150% DPI で、`right_min`（論理 415 / 物理 415・519・623）とパッドの可読性。
- パッドを上へ移した実際の `pad_bottom`（推定 336〜346 / 125%）。
- `tabs_right` + 実行バーを入れた 1280×720 の実画面（映像 727×409、ログ 180、右列 523）。
- 640 / 1024 / 1280 / 1920 の切り替えヒステリシス（実行時しきい値。125% の例で論理 800 / 840、物理 1000 / 1050）。
- 640 のフォールバックに実行バーを出した状態で、接続 / 切断がまだ見えるか（現行の y=370 はバーなしの実測。バー 30px で約 171px に縮む見込み）。
- ログのピン留めを畳んだ状態で、✖ / ⚠ の件数がクリックできること。

これらを測るまでは、`tabs_right` を既定にしない。設計としては、幅・高さ・DPI の条件を入れておけば、どの DPI でも既定にできる形になる。

# 詳細 UI 監査 — レイアウト以外の「中身」と文言

対象: `a515503` / 2026-11-01。これまでのレビューは「窓の区画・寸法・切り替え」に集中しており、**画面の中身（何が隠れているか、手動のままか、ラベルが実態と合っているか）**はほぼ未検討だった。ここではその 3 点を個別に見る。

---

## 0. 結論

- **種別・接続方式を折りたたみに置くこと自体は妥当**。ただし「現在の値」がタブ内に見えず、切り替え後の再接続も手動なので、隠すと「今どれで動いているか」が分からなくなる。
- **自動化できるのに手動のまま**の箇所が複数ある。特に BCON の再起動後の再接続は、確認 → 待つ → タブ → 一覧更新 → ポート選択 → 接続 → HELLO の 7 手順で、自動化の効果が大きい。
- **ラベルが実態より強い**箇所がある。「診断・送信ログ」にログはなく、「接続し直す」はタブを開くだけ、「現在の方式」は表示ではなく問い合わせ、「種別」は現在値がない。「取込を破棄」と「ペア鍵を全削除」は同じフレームを送っている。

---

## 1. BCON の種別・接続方式・ペアリング

### 現状

| 項目 | 置き場所 | 現在の見え方 |
|---|---|---|
| 接続方式（有線 / 無線） | `接続モード・ペアリング` 折りたたみの中 | `有線にする` / `無線にする` / `現在の方式` の 3 ボタン。現在値の常設表示はない |
| 種別（Pro Con / Joy-Con L / R） | 同じ折りたたみの中 | 3 ボタン。どれが現在かは表示されない |
| ペアリング取込 | 同じ折りたたみの中 | 取込時間 + `取込開始` + `保存した入力を再生` |
| 状態 | `コントローラ状態`（常時） | プレイヤーLED、ジャイロ、振動。接続方式・種別は出ない |
| 再起動後の復帰 | `操作` の `Switchへ再接続`、または `シリアルタブで接続し直す` | 後者は**タブを開いて一覧を更新するだけ**で、接続はしない |

### 判断

- **折りたたみは維持してよい。** 接続方式・種別・ペアリングはセットアップ寄りで、日常の「開始 / 停止 / 手動操作」より頻度が低い。常時出すと事故（誤クリックで再起動）が増える。
- ただし、**「今の値」だけは折りたたみの外に出す**べき。折りたたみの見出しを `接続モード・ペアリング（現在: 無線 / Pro Con）` にする、または `コントローラ状態` に 1 行足す。
- 接続方式は STATUS から読める。**種別は現行コードに読み取り経路がない**（`set_emulate_mode` を送るだけで、現在値を問い合わせていない）。読めないなら「最後に設定: Pro Con（未確認）」と明記する。現在値と誤認させない。
- 3 つのボタンは「押すと変わる」だけで、選択状態がない。**現在値を読めるまではラジオにしない**。ボタンのまま「最終設定: Pro Con（未確認）」を出し、押した後に「設定中 → 再起動 → 未確認」を出す。

### 再起動後の復帰（手動のまま）

- `_confirmed_method(..., restarts_device=True)` は入力停止 → 再起動 → `phase="restarting"` にし、`"ポートが戻ったら『更新』→『接続』"` と表示する。
- 実際の手順は、**一覧更新 → ポート選択 → 接続 → HELLO 待ち**。ユーザーは BCON タブからシリアルタブへ移り、もう一度操作する。
- `シリアルタブで接続し直す` は `_show_serial_for_recovery` を呼ぶだけで、`setting_nb.select(tab_serial)` と `refreshComPorts()` のみ。**接続はしない**。ラベルと動作が一致していない。

**提案**

1. `シリアルタブで接続し直す` を実際の再接続にする（一覧更新 → 保存済みポートを選択 → `reloadSerialPort()`）。
2. さらに、再起動後に**自動でポートを待って再接続**する。0.5 秒間隔で初期 15 秒（設定可）、`serial_number` が一致する機器を探し、見つかったら接続 + HELLO。進捗と「中止」を出す。BOOTSEL は対象外。
3. 種別・方式の変更確認に「再起動後、自動で再接続します」と書く。手動手順の説明を消す。

リスク: COM 番号の再利用、別の Pico を掴む、HELLO 失敗。**照合は `pyserial` の `serial_number`**（VID/PID は全個体同じなので不可）。`serial_number` が取れない個体は自動せず手動へ。

## 2. 自動化できるのに手動のままの箇所

| # | 操作 | 現在の手順 | 自動化案 | リスク |
|---|---|---|---|---|
| A1 | BCON 方式 / 種別変更後の復帰 | 確認 → 待つ → シリアルタブ → 一覧更新 → ポート選択 → 接続 → HELLO | 再起動待ち + 自動再接続（上記）。**照合は `pyserial` の `serial_number`（Pico の固有 ID）**。VID/PID は全個体同じなので使わない。`serial_number` が取れない個体は自動せず手動へ。待ちは **15 秒を初期値に設定可能**。**有線モードで PC 側 CDC が戻るかはモード別に要確認**。戻らない構成は自動対象外 | 中。ポート取り違え、HELLO 失敗。読み取りは再試行可、書き込みは不可 |
| A2 | `シリアルタブで接続し直す` | タブ移動 + 一覧更新のみ | 実際に再接続する 1 ボタンに | 低 |
| A3 | ペアリング取込の成功後 | 「取込を保存しました。」→ 自分で `Switchへ再接続` を探して押す | 成功メッセージの隣に `Switchへ再接続` を出す。自動実行はしない | 低。ユーザーが結果を確認してから押せる |
| A4 | BCON タブを開いたときの状態 | `状態を更新` を押すまで古い写しのことがある | タブ表示時に STATUS_REQ を 1 回だけ送る。**`runner.is_busy()` の間は送らない**。最小間隔（2 秒）を設ける | 低。読み取りのみ。実行中の割り込みを避ける |
| A5 | 再起動後のポート一覧 | `一覧更新` を押す | A1 に含める | 低 |
| A6 | カメラ / オーディオの再列挙 | `再読み込み` を押す | デバイス変更を監視して自動再列挙 | 中。ハードウェア依存。後回し |
| A7 | ゲームパッドの再接続 | 2 秒の自動巡回 + 手動 `再接続` | 既に自動。手動は「詰まったとき」用でよい | — |
| A8 | 通信速度の探索 | `速度を探す` を押す | 自動化しない | 高。書き込み・誤通信の可能性 |
| A9 | コマンド一覧の再読み込み | F5 / `再読み込み` | ファイル監視で自動 | 低〜中。編集中の一時ファイルを拾う。優先度低 |

**原則**: 自動再試行してよいのは冪等な読み取り（STATUS / PING / ポート列挙）だけ。再起動・モード変更・キー削除は自動で繰り返さない。A1 は「再起動後の復帰」だけを自動化し、変更操作そのものは確認ダイアログのままにする。

## 3. ラベルと中身の不一致

| ラベル | 実際の中身 | 問題 | 修正案 |
|---|---|---|---|

## 7. 判断が必要なこと

- **種別切り替えはどのくらい頻繁か。** セットアップ時だけなら折りたたみのままでよい。ゲームごとに切り替えるなら、種別だけ常時見えるクイック行にする。
- **種別の現在値をプロトコルから読めるか。** 読めないなら、設定に「最後に送った種別」を保存し、`未確認` と添える。現在値と偽らない。
- **再起動後の自動再接続を許すか。** `serial_number` が一致するときだけ、初期 15 秒（設定可）。失敗時は手動へ戻す。有線モードで CDC が戻るかは別途確認。
- **`取込を破棄` と `ペア鍵を全削除` は同じ操作か。** 同じなら 1 つに統合。違うならフレームを分ける。
- **状態バーの `Pico↔Switch` を自動で隠すか。** BCON 以外では意味がない。

## 4. レビュー提案への補正

- **「BCON の警告は常に表示」は誤り。** 警告は `接続モード・ペアリング` を開いたときだけ出る。確認ダイアログにも警告があるので、静的警告を削ってダイアログへ寄せる提案自体は妥当。
- **「タブ内のボタンが実行バーと重複」はまだ起きていない。** 実行バーは標準レイアウトに出ていない（コンパクトのみ）。`tabs_right` + 実行バーを入れた後に整理する。
- **シリアルの 1 行化は右列 523 物理＝418 論理（125%）、タブ内容 498 物理＝398 論理でぎりぎり。** `⟳` を 32px とすると見積もり約 434 物理。方式・ポートの表示名が長いため、実測前に「1 行で収まる」と決めない。
- **デッドゾーンの範囲は 0〜8192 ではない。** 実際は 0〜32767 の生軸。既定 1638 は 5%。UI の上限 8192 は 25% までしか設定できない。% 表示にするなら範囲も直すが、**上限は 50%（16383）**にする。100% はスティックが反応しない。
- **入力調停の選択肢は英語の内部値。** 設定ファイルの `off` / `human` / `script` は変えず、**表示名だけを対応づける**。

## 4.1 補足仕様（実装時に1行ずつ足す）

### 接続 / 再接続 / 切断

- ボタンは分けたまま。**接続中は `接続` を無効化**（または `接続済み`）し、`切断` だけ押せる。
- `再接続` は `接続(N)` メニューへ移す。現行の「接続 → 再接続」は、接続中に押すと通信を切り直すため、誤クリックの影響がトグルと同等。無効化で防ぐ。
- 接続失敗時は `接続` を再び有効化し、失敗理由の横に `速度を探す` を出す。

### シリアルの1行化

- `一覧更新` をアイコン `⟳`（約32px）にすると、現行見積もりから約66px 空く。
- それでも右列 498 物理（398 論理）に入らない場合は、表示名を短くする（`USB直結` / `Pico中継(USB)` / `Pico中継(プロセス)`）。正式名はツールチップ。
- 1行化の前に **498 物理（398 論理 / 125%）で実測**。入らなければ2行（方式 / ポート+接続）。

### 失敗時だけ出す復旧

- 表示条件: **最後の接続試行が `failed`**。
- 消す条件: **接続成功（`ready`）**、または**通信方式 / ポートを変更**したとき。
- `速度を探す` は失敗時だけ基本表示に出す。診断の `HELLO` / `PING` は `ツール(T)` に置く。

### スティックの遊び（デッドゾーン）

- 保存値は既存のまま読む（現行の保存値は 0〜8192 の範囲内）。UI の範囲を 0〜16383 に広げても、既存値の**挙動**は変わらない。ただし旧 UI で 8192 を 100% と思っていた場合は、25% と表示される。
- 表示は `%`。`pct = value / 32767 * 100`、`value = round(pct / 100 * 32767)`。丸めは 1 か所の関数にまとめる。
- 既定 1638 は 5%。スライダー + 数値入力（生値）を併用し、精度を残す。
- `config.complete_missing` の検証上限も **16383（50%）** に合わせる。100% を許さない。

### 入力調停の表示名

- 設定ファイルの内部値 `off` / `human` / `script` は変えない。
- 画面の表示名だけ `両方受け付ける（本家）` / `手動を優先` / `コマンドを優先` に対応づける。`applyArbitration` で表示名→内部値へ戻す。

## 5. 実装順（推奨）

0. **破壊的操作とラベルの確認（最優先）**
    - **0a. 破壊的操作**: `取込を破棄` と `ペア鍵を全削除` が同じ `T_KEY_DELETE` + `b""` を送る件。ファームウェアの 0x33 の意味を確認するまで、両方の確認ダイアログを同じ強さにし、`取込を破棄` の文言に「ペア鍵も削除される可能性」を明記する。確認後、同じ操作なら統合、違うならフレームを分ける。
    - **0b. ラベルと動作**: `シリアルタブで接続し直す` がタブ移動 + 一覧更新だけの件。**実際に再接続する**か、`シリアルタブを開く（一覧更新）` に改名する。名前と動作を一致させる。
1. **文言・状態の修正**（低リスク）: デッドゾーン範囲 / 入力調停ラベル / `HELLO: 対象外` / 空表示 / 接続ボタン幅 / `Pico↔Switch` の BCON 限定 / `fps` 既定オフ / 手動入力の未接続非表示
2. **1 項目折りたたみの廃止 + メニュー移設**: 通信速度、診断、ゲームパッド調整、入力調停、マウス、BCON 色、保守
3. **1 行化**: コマンド検索、カメラ、オーディオ、コントローラ。シリアルは実測して 1 行 / 2 行を決める
4. **タブ統合**: カメラ + オーディオ、履歴 + コマンド。`tabs_right` と 640 の結果を見てから
5. **実行バー / 常設停止**を入れた後に、履歴の停止・重複ボタンを整理
