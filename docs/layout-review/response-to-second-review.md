# 追加レビューへの回答 — `tabs_right` の穴を埋める

対象: 2026-11-01 / 1280×720（125% DPI）の実測。追加レビューの 3 点（640 幅、右列幅、ログ高さ）は**すべて実在**します。 なお、この文書の `left_min=480` / `1003` / `1040` は暫定の物理px値。**最終的な単位と値は `response-to-third-review.md`（すべて論理px、`left_min=380`、800/840）を正**とする。ただし、いくつか補正と、実装前に決めるべき追加条件があります。

## 1. 640 幅のフォールバック（実測）

`log_right` のままログを非表示にすると、640×480 では次のようになります。

| ウィンドウ | プレビュー | タブ欄 | 接続ボタン | 横スクロール |
|---|---|---|---|---|
| 640×480 | 616×171 | 630×201 | 12,370 / 482×30（見える） | なし |
| 1024×600 | 1000×236 | 1014×256 | 12,435 / 866×30（見える） | なし |
| 1280×720 | 1256×301 | 1270×311 | 12,500 / 1143×30 | なし |

- 640 ではタブ本文の見える高さが 201px しかないが、**接続 / 切断は y=370 で画面内**に入る（横スクロールバーが消えて高さが戻るため）。下部の詳細は縦スクロールになる。
- したがって追加レビューの「log_right でログを畳む」フォールバックは有効。**保存しない一時状態**にし、幅が戻ったらログを復元する。
- ただし `tabs_right` のまま 640 にはできない。右列 523 を確保すると左は 117px しか残らない。**幅の条件で `tabs_right` を諦める**必要がある。

### 幅の条件（案）

- `right_min` = パッドの要求幅 × 許容縮小率 + タブ枠・余白（実測 46px）。
  - 125%: `525 × 0.9 + 46 = 518.5` → **523**（実測の右列 523 と一致）
  - 150%: `630 × 0.9 + 46 = 613`（未検証）
  - 100%: `420 × 0.9 + 46 = 424`
- `left_min` = 映像列の最小幅。**暫定 480**（最終は論理 380。`response-to-third-review.md` を正とする）。
- `W >= right_min + left_min` のとき `tabs_right`、満たさないときは `log_right` + ログ非表示。
  - 1280 / 125%: 1280 ≥ 523+480=1003 → `tabs_right`
  - 1024 / 125%: 1024 ≥ 1003 → `tabs_right`（ただし高さ条件は別）
  - 640: 640 < 1003 → フォールバック

`left_min` を 320 にすると 843 以上で `tabs_right` になる。どちらが良いかは、映像の最小実用サイズで決める。**固定値をコードへ散らさず、1 か所の定数にする。**

## 2. 右列の幅と、広いウィンドウでの伸び

追加レビューの「右列を比率で持つと 1920 で太る」は正しい。現行の `pane_sashes` は比率保存なので、そのまま `tabs_right` に使うと、1920 で右列が約 785 になり、左の映像に回らない。

### 実装案

- 右列（タブ）の `weight=0`、左列（映像 + ログ）の `weight=1`。余った幅は左だけへ配る。
- ただし `ttk.PanedWindow` の初期仕切りは要求サイズで決まるため、**初回だけ `sashpos` を右列幅で置く**必要がある。
- 比率保存（`pane_sashes`）は `tabs_right` では使わない、または「右列の px」を別キーで保存する。比率のまま保存すると、次回起動時にまた比率で広がる。
- 右列の下限は `right_min`（上記）。ウィンドウを狭めて `right_min` を割る場合は、フォールバックへ切り替える。

### 数値の整合

- 右列 523 → タブ内のパッドは 477×202（scale 1.14 / 基準 1.25 = **91%**）。
- 「パッド 525 を下限」にするなら、右列は **571**（=525+46）。
- 91% を許容するなら 523 でよい。**どちらを採るかを先に決める**必要がある。画面で 91% が読めることは確認済みだが、正式な下限は実機で決める。
- 150% では、右列 613（91%）/ 676（100%）。1280 幅なら 613+480=1093 で `tabs_right` は成立するが、高さは別。

## 3. `tabs_right` の高さ条件

- 1280×720: タブ枠 684、見出し 31、本文 653。内容 635 → **余裕 18px**。
- HidHide 未設定の案内行（約 30px）が出ると 665 > 653 で溢れる。**パッドを上へ移す並べ替えは同時に必要**。
- 1024×600: タブ枠 564、本文 533。内容 635 → **102px 足りない**。パッド並べ替えをしても、全体はスクロールする（パッド自体は見える）。
- 640×480:  `tabs_right` は幅で不成立。フォールバック。

高さの条件は「全内容 635px が収まること」ではなく、**「パッドの下端が見えること」**にする（推定 336〜346px / 125%）。720 も 600 もパッドは見える。全内容が収まるのは 720 でも HidHide 行が無い場合だけ。

## 4. ログ欄の高さ

`tabs_right` の左列は `V[preview(+実行バー), log]`、重み 3:1。

- 1280: 左列 684 → ログ **約 171px**。
- 1920: 左列 1044 → ログ **約 261px**。
- ログ内部: タブ見出し 31 + ツールバー 30 を引くと、1280 では約 110px を「ログ」と「結果とエラー」で分ける。各 1〜2 行。
- ログを 200〜220px に増やしても、1280 の映像は 409px を保てる（プレビュー 464、バー 30、映像 409）。**ログの重みを 3:1 から 4:1.5 程度へ上げる余地はある**。

### 左右並べは作り直しになる

`ttk.PanedWindow` の `orient` は read-only（`configure(orient=...)` はエラー）。ログの上下分割を左右分割へ変えるには、`log_pane` を作り直す必要がある。先にやるなら、**「結果とエラー」の段を畳む / ツールバーから開く**方が小さい。

- `pin_frame` を `forget` して、ログのツールバーに「結果とエラー」トグルを置く。
- もしくは `tabs_right` のときだけ `log_pane` の sash を下端へ寄せ、ピン留めを最小化する。
- どちらも「ログ 2 段を同時に見せる」ことは諦める。2〜3 行で足りるなら現状維持でもよいが、**決めてから実装する**。

## 5. Q7 の順番（補正）

追加レビューは「実行バーを先に」と言うが、単独で入れると `log_right` の映像が縮む。

- 現行 `log_right`: プレビュー本文 301、映像 535×301。
- 実行バー 30〜34 を足すと、プレビュー本文 267〜271、映像は約 475×267。
- `tabs_right` と同時なら、映像 727×409 を保てる。

したがって順番は:

1. **`tabs_right` + 実行バーを同時に**（右列幅・高さ条件つき）
2. **狭い幅のフォールバック + 状態バー優先度**（640 の接続を守る）
3. **パッドを折りたたみより上へ**（HidHide 行を含めて余裕を確保）
4. ログのピン留め畳み / 状態バーの色 / 履歴ボタン / 検索プレースホルダ

3 は 1 と同時でもよい。1 の余裕が 18px しかないため、**3 を後回しにすると HidHide 未設定の環境でスクロールが残る**。

## 6. 小さな指摘への回答

- **右列を最小幅にした再測**: 右列 523 でタブ内容 498。シリアルの 2 列化しきい値は 470 なので、**2 列のまま**（余裕 28px）。右列を 500 まで詰めると 475、490 で 465 となり 1 列化して高さが増える。`right_min=523` はこの境界のすぐ上なので、**右列最小幅では必ず再測**する。
- **既定値の移行**: 既存ユーザーには効かない。ユーザーが少数なら「表示(V) > 右にタブとログ」系のメニュー案内で十分。設定に版番号を足すのは、移行を自動化したい場合だけ。
- **150% DPI**: 右列 613 / 676、タブ内容も拡大する。1280×720 では高さが足りない可能性が高い。**実測するまで `tabs_right` の既定化はしない**。

## 8. まとめ

- 追加レビューの 3 つの穴は、すべて実装前に決めるべきです。
- ただし「右列 523〜530 でパッド 525 を満たす」は誤り。523 は 91% 許容の値で、1:1 は 571。
- 640 のフォールバックは `log_right` + ログ非表示で成立する（実測）。
- `tabs_right` は 1280×720 でも余裕 18px。HidHide 行とパッドの並べ替えをセットで扱う。
- 実行バーは単独で入れると映像が縮む。`tabs_right` と同時が安全。
- 1024×600 では `tabs_right` でも全体はスクロールする。高さ条件を分けて扱う。
