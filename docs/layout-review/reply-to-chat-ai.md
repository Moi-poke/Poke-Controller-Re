## 1. 0x33（BCON KEY_DELETE）の確定

- BCON の `0x33` は **Classic リンク鍵の全削除 + 保存ホスト（BCHO）の削除**。ペイロードは LEN=0 固定。
- **取込（`BCW1`）は消えません。** 取込を消すフレームは BCON の仕様に存在しません。
- 仕様: `Moi-poke/Switch-bcon` の `spec/protocol_v3.md`:
  `0x33 | KEY_DELETE | PC→Pico | 0 | Classicリンク鍵全削除`
  https://github.com/Moi-poke/Switch-bcon/blob/main/spec/protocol_v3.md#L123
- 実装: `src/main.c` の `FX_KEY_DELETE` が `gap_delete_all_link_keys()` と `store_host_forget()` を実行。
  https://github.com/Moi-poke/Switch-bcon/blob/main/src/main.c#L1036-L1040
- 有線起動時は `s_bt_init == false` のため `gap_delete_all_link_keys()` はスキップされ、host タグだけ消えます。
- `pico-wakeCon` には `X`（取込破棄）と `K`（鍵削除）が別コマンドとしてありますが、BCON は `K` 相当だけを `0x33` に移植しています。

UI 側:
- 送るフレームは `0x33` の 1 種類、ペイロードは LEN=0 固定。中身の比較は不要。
- 重複していた `取込を破棄` を削除し、`ペア鍵を全削除` 1 つに集約。
- 確認文に「取込は残る」を明記。
- **有線モード（STATUS flags bit5）ではボタンを disabled** にし、「有線モードでは鍵を削除できません。無線で起動してください。」を表示。
- 直接呼ばれても送信しないガードを追加。

## 2. DPI と実測条件

- `tk scaling` は **1pt（1/72 inch）あたりの px**。125%（120dpi）では `120/72 = 1.666`。DPI 倍率は `winfo_fpixels("1i") / 96 = 1.25`。
- 修正前:
  - SDL（既定）: process awareness **0（DPI unaware）**、window 96dpi、Tk scaling 1.333、画面は 3072×1728 に仮想化。
  - GDI: Tk 初期化後に `SetProcessDPIAware()` が走り awareness 1 になるが、Tk scaling は 1.333 のまま。window だけ 120dpi になり、UI が小さくなる。
- 修正: `Window` の Tk 作成前に `SetProcessDPIAware()` を呼ぶ。
  - 実測: awareness **1（system DPI aware）**、window 120dpi、`winfo_fpixels("1i")=120`、Tk scaling 1.666、画面 3840×2160。
- これは system DPI aware。モニタ間で DPI が変わっても OS がビットマップ拡大縮小し、`WM_DPICHANGED` は不要。
- per-monitor にする場合は、Tk 作成前に `SetProcessDpiAwareness(2)` を呼び、`WM_DPICHANGED` を受けて再配置する必要がある。

## 5. レイアウトに説明させる方針

説明用のセカンダリラベルは原則として削除し、配置・順序・整列・近接で伝えます。ただし、**今の状態**と**押せない理由・次にすべき操作**は、対象の横に短い状態表示として残します。

- 同じ目的の操作は同じ見出しの下に置く
- 上から下、左から右へ作業順に並べる
- 状態・理由・次の操作は対象の操作の近くに置く
- 入力欄は内容の長さに合わせ、ラベル位置を揃える
- 押せない操作は disabled にし、押せる操作との差を配置で見せる
- 押せない理由と次にすべき操作は、対象の横に短い状態表示として出す（例: `ポートを選ぶと接続できます`、`有線では削除できません。無線で起動してください`）
- 今の状態（接続方式・種別）は折りたたみの外に残す
- 説明文を足す前に、配置で分からないかを見る
- 長い説明はツールチップへ
