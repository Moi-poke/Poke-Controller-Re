# IMU（ジャイロ）経路

`AGENTS.md` から分離したサブシステム固有の注意点である。IMU・HID・ジャイロ・0x30 / 0x40 に触るときだけ参照する。

- **PC→Pico の送出と 0x30 スロット**: PC→Pico は `T_IMU_SAMPLE`（0x04 / LEN12、`ax,ay,az,gx,gy,gz` の 6 × int16-LE）を通常 5ms 間隔で送る。0x30 は 5ms 間隔の 3 スロットを持ち、送出周期は **15ms** である（これより速い反復は過積分の恐れがある）。Pico は 0x30 生成までに届いた試料を消費し、3 件ならそのまま古い順、4 件以上なら古い分のジャイロ角度を先頭スロットへ合算する。届いた試料がなければジャイロ 0、加速度は最新姿勢を保持する。Pico へ反映するには更新した `Switch-bcon` ファームウェアが必要である。
- **0x40 の引数は IMU 形式の選択**: 実測では FW 4.51 → `02`=圧縮クォータニオン、3.72 → `01`=RAW である。FW は引数を `imu_mode` として保持し、1 なら RAW 36B、2 なら NS-LIB-HID `ns_mode_2_s` 同形の 36B（accel y,x,z＋最大成分基準の 30bit クォータニオン＋11bit ms）を返す。`3` は未解明として仮定しない。**現行の実機検証は 3.72＋RAW**（Mario Tennis / Splatoon で確認）であり、4.51 を名乗る場合は mode2 のクォータニオン経路が必須である。
- **有線 0x30 の role 制限と診断フラグ**: 有線 0x30 の IMU は既定で role0 のみである（`usb_imu_wired_role_ok`）。role1 / 2 で有線ジャイロを試す診断には `JOY_WIRED_IMU_ALL=1` を使い、FW 版の A/B 切替には `JOY_USB_FW_JOY_OLD=1`（Joy 役を 3.72 にする）を使う。
- **role2 の軸写像と校正**: role2 の軸写像は FW 側で固定されている（`k_joy_negate_axis`: 加速度・ジャイロとも Y, Z 反転）。SPI 校正値の回転だけ `JOY_SPI_CAL_ROT`（0=なし / 1=YZ / 4=XZ）で切り分けられる。PC 側 `[IMU] accel_*/gyro_axes・signs` は恒等が前提であり、HID 直結でも適用される。
- **不感帯とトリム**: `[IMU] gyro_dead_dps` は送出直前のジャイロ各軸に効く（`core.imu_wave.apply_gyro_deadband`）。既定 0（無効）で小さい動きを残し、必要なら 1〜3 程度を入れる。`gyro_scale` は実測用トリムである。なお、**加工後の値を返さないと不感帯が送出に効かない**（過去に実際に踏んだ不具合である）。
- **HID リーダーの共有ハンドル**: HID リーダー（`core.nintendo_hid`）はプロセス共有の読み取り専用スレッドが最新の 0x30 を保持する。`ImuPanel` は停止時に共有ハンドルを閉じない。読取失敗が続いたらリーダー自身が閉じ、パッド / IMU 側が再オープンする（UF2 書き込みで USB が再列挙されるため必須である）。
- **IMU パネルの入力源**: 通常は **「パッドAPI」（SDL）／「HID直結」／「マウス」**（Windows のみ）を表示する。`sine` / `step` / `rest` / `manual` および反転・感度・詳細表示は**デバッグ**時だけ出す。ボタンは「開始/停止」である。

## マウスでジャイロ

IMU パネルの入力源「マウス」で、PC のマウス移動をジャイロとして送る。Windows の Raw Input（`WM_INPUT`、`RIDEV_INPUTSINK`）を使うため、ポインタ加速や画面端の影響を受けない生の移動量（count）で動く。Windows 以外では入力源の候補に出さず、設定に `mouse` が残っていても `パッドAPI` へ寄せる。送り先は BCON の `T_IMU_SAMPLE` 経路（`switch-bcon` / `switch-bcon-proc`）であり、入力は既定 5ms 刻み、Switch への 0x30 報告は約 15ms 刻みとなる。

- **設定欄**: 「ジャイロ設定」を開くと、入力源の直下にその入力源の操作が出る。マウスの感度計算と詳細調整は必要なときだけ開く。記録先の指定は「送出値を記録する」にチェックを入れると表示される。
- **開始/停止**: 入力源を「マウス」にして「開始」を押すと、キャプチャと送出を同時に始める。「停止」で両方を止める。
- **解除**: キャプチャ中はカーソルを非表示にし、PokeCon のクライアント領域へ閉じ込める。解除はグローバルホットキー（既定 `Ctrl+Alt+M`）か「停止」で行う。PokeCon が前面から外れたときも自動で解除し、クリップも外れる。ホットキーで解除しても送出は続き、ジャイロは 0（静止）を送る。再度ホットキーを押すと、PokeCon が前面にある場合だけ再開する。
- **GUIロックとEsc**: キャプチャ中は Tk のマウスイベントを全ウィジェットで止めるため、GUI のボタンや仮想パッドを誤クリックしない。停止は **Esc** で行う（「停止」ボタンと同じく、送出中の入力源なら種類を問わない）。キャプチャ中は入力欄などが Esc を消費しても停止を優先する。Esc は PokeCon のメイン窓とジャイロ欄の窓だけで受け、グローバルホットキーにはしない。開始・解除のたびに、仮想パッドとカメラ面で掴んでいたマウススティック／ボタンを解放する（再開後にマウス操作が入力を上書きしないため）。
- **仮想姿勢と3軸**: マウス X は**ワールドの鉛直軸まわり**（水平に振り向く）、マウス Y は**機体の横軸まわり**（上下を向く）として、ホスト側の目標姿勢 `q_target` を更新する。生成済み raw を積分した姿勢 `q_output` との差分 `q_output^-1 * q_target` を機体座標の回転ベクトルへ直し、5ms あたりの 3 軸 raw へ量子化する。ピッチを付けた状態でヨーを振ると機体 X（ロール）にも成分が出る。加速度は `q_output^-1 * 静止重力` である。`q_output` はゲームの実測姿勢ではなく、送出生成値から計算したホスト側の姿勢である。ファームウェアへのコマンドは既存の 6 値送信のままとする。
- **角度の保存**: ホストの量子化端数は次のサンプルへ繰り越す。差分が `mouse_backlog_deg`（既定 30°）を超える速いフリックは超過分を捨てる。Pico では 0x30 間に 3 件を超える試料を受けた場合、古いジャイロ値を先頭スロットへ合算し、最新の加速度を使う。ただし 3 枠の表現範囲を超える合算値は飽和し、0x30 が 100ms 以上止まれば古い動きは捨てる。
- **軸・符号**: `mouse_yaw_axis` は**ワールドの鉛直軸**（既定 Z）、`mouse_pitch_axis` は**機体の横軸**（既定 Y）である。右への移動が右向きのヨー、下への移動が下向きのピッチになる符号を既定にしている。実機の向きが違う場合は画面の「左右反転」「上下反転」で直す。軸・符号の上書きは `mouse_yaw_axis` / `mouse_pitch_axis`（0..2）と `mouse_yaw_sign` / `mouse_pitch_sign`（+1 / -1）で行う。
- **ピッチ上限**: `mouse_pitch_limit_deg`（既定 89°）は真上・真下付近でヨー軸が定まらなくなるのを避ける上限であり、超える入力はそこで止まる。
- **ロール**: 画面の「ロール」で `none` / `右ボタン` / `Shift` を選ぶ。修飾中はマウス X がワールドヨーではなく機体のロール軸（`mouse_roll_axis`、既定 X）まわりになる。`mouse_roll_sign` で向きを反転する。右ボタンはキャプチャ中に GUI クリックを止めているため競合しない。設定は次の `WM_INPUT` から効く。
- **姿勢リセット**: 既定 `Ctrl+Alt+R`（`mouse_reset_hotkey`）または画面の「姿勢リセット」で、仮想姿勢を水平・正面へ戻す。マウスでは手を元の位置へ戻す自然な復帰ができないため、ピッチ・ロールがずれたときはゲーム側のリセンターと併用する。リセット直後はジャイロ 0・静止重力を送る。
- **感度**: `mouse_sensitivity` [deg/count]（画面の「感度」）と `mouse_ratio_y`（上下の比）を使う。マウスの DPI を変えたら感度を測り直す。`gyro_scale` はデバッグ時に表示する「送出倍率」であり、送出直前の倍率である。`gyro_dead_dps` はマウス源では適用しない（遅いエイムが止まるため）。
- **感度の逆算**: 「感度を距離から計算」を開き、「DPI」と「360°距離」にマウスの DPI と目標距離（例: 20cm）を入れ、「計算」を押すと `感度 = 360×2.54 / (DPI×cm)` で設定する。下の「現在 xxcm/360°」は今の感度での実距離を示す。Raw Input の count は DPI そのものであり、Windows のポインタ速度・加速は乗らない。DPI はマウス付属ソフトの設定値を使う（DPI が不明なら、近い値を入れて「現在」の表示と実際のマウス移動距離を突き合わせて補正する）。`mouse_dpi` / `mouse_cm_per_360` は ini にも保存される。
- **平滑化**: `mouse_smoothing`（0.05..1.0、既定 1.0）は画面の「詳細調整」内にある。小さくするとパルスは広がるが、操作遅延が増える。遅延が気になる場合はまず 1.0 のまま送達経路を調べる。
- **周期**: `mouse_interval_ms`（1..20、既定 5）は 0x30 の 5ms × 3 に合わせ、通常は 5 のまま使う。異なる周期では 1 サンプルの角度の解釈がずれる。画面の感度・上下比・平滑化・反転は確定（フォーカスを外す / Enter）で保存し、送出中なら次のサンプルから効く。ロール修飾は次の `WM_INPUT` から、解除・リセットのホットキー変更は次の開始から有効になる。
- **プロトコル**: 新しいコマンドは足さず、既存の `T_IMU_SAMPLE`（BCON フレームの seq・チェックサム）をそのまま使う。計画書の「角度増分コマンド」は現行構成では不要である。
- **ジャイロ係数**: `mouse_deg_per_lsb`（既定 0.06103）は、SPI 較正値や実機ダンプで係数が違う場合の上書き口である。
- **ポーリングレート**: 送出中の統計行 `入力=NNN/s` が、実際に受け取っている Raw Input のイベントレート（マウスを動かしている間）を示す。停止中に単体で測るときは `uv run --frozen python tools/probes/mouse_rate.py --seconds 5` を実行する。
- **生波形の階段**: 1 カウントは `感度 / (0.06103×0.005)` raw である。感度 0.0381 なら約 125raw の 5ms パルスになる。整数カウントによるギザギザは波形の見た目だけでは遅延の証拠にならない。同じ cm/360° のまま DPI を上げると 1 カウントの角度は細かくなる（感度も同じ比率で下げる）。ただしゲーム側の不感帯が不明なまま DPI や平滑化を変えても、微動の反映が改善するとは限らない。
- **重力追従**: 画面の「詳細調整」にある。既定は `q_output` から毎サンプル重力を計算する。ゲームが重力でピッチを水平へ戻す場合も、仮想コントローラーが実際に傾いた状態と一致する。`mouse_gravity_follow=0` で固定重力に戻せる（比較用）。
- **対象外**: 振る動作（加速度の急変）はマウス移動からは作らない。必要であれば実機ダンプの加速度・ジャイロ波形を数十 ms 流す別機能にする。

**未検証（実機での確認が必要）**: 軸の割り当てと符号、ロールの向き、ピッチ上限、`mouse_deg_per_lsb` の実機一致、0x30 での送達率、ゲーム内の感度・遅延は未検証である。ホストは `q_target` / `q_output` の差分から raw へ量子化し、Pico は**別の段階で**未報告の raw を 0x30 の 3 枠へ配分する。古い「最新3件」方式のファームウェアには後者の改善がない。

`switch-bcon-proc` は子が詰まったとき、未送出 IMU を最大 100ms 分だけ保持し、ジャイロ値を合算して送る。超過した古い値や停止・hold 中の未送出値は `imu_stats()["stale"]` に数える。`sent` は親が受理した試料数、`frames` は子へ投入したフレーム数、`delivered` は子がシリアルへ書けたと応答したフレーム数であり、Switch への到着確認ではない。合算で角度を守っても、停滞中の時間を短い報告へ圧縮するため、ゲーム内の動きの滑らかさと遅延は実機で比較する。

## 3D ジャイロプレビュー

ジャイロ欄の「3Dプレビュー」で、姿勢を確認する別ウィンドウを開く。入力源を選んで「開始」を押すと、パネルが送出するサンプルに合わせてモデルが回転する。送出前でも窓は開けるが、サンプルが届くまでは「待機中」と表示する。中立姿勢ではボタン面を正面から表示する。固定の斜め視点は使わず、コントローラーを傾けた分だけモデルが傾く。モデルの背景は明るいグレーにし、黒い筐体の輪郭を見分けやすくしている。

- **モデル切替**: 上部のボタン、または `1` / `2` / `3` キーで、プロコン、Joy-Con (L)、Joy-Con (R) を選ぶ。切替は外観だけで、入力源や送出値は変えない。
- **正面リセット**: ボタンまたは `R` キーを押した時点の持ち方を、新しい正面の基準にする。左右の向きと傾きを含めてボタン面が真正面を向き、その後は基準から動かした分だけ追従する。入力停止中も最後の受信姿勢で即時に反映し、まだ未受信なら最初に届いた姿勢を基準にする。表示だけの補正であり、送出値は変えない。
- **終了**: 窓の閉じるボタンか `Esc` で閉じる。プレビューを閉じても送出は続き、再度「3Dプレビュー」を押せば開き直せる。
- **入力停止**: 0.5 秒以上サンプルが来ないと姿勢を最後の向きで止め、「入力停止」と表示する。ボタンとスティックは中立に戻す。

姿勢は、符号、感度、不感帯などを適用した **パネルの送出値** から計算する。「記録の再生」でも姿勢を表示できるが、マクロが独自に開始した送出はこの窓の対象外である。ジャイロを積分し、加速度が約 1g のときに傾きを補正する。磁気センサーを使わないため、左右の向きはドリフトする。

モデルは実物を参考にした手続き生成の形状であり、スキャンデータではない。プロコンは mm 単位で定義した筐体形状をメッシュ化し、Joy-Con は外側とレール側で角の丸みを変えている。グリップ、スティックのくぼみ、ボタンの文字、継ぎ目やレールを描き、文字と可動部は取り付け面に沿って動く。スティックの球状の根元と軸は明るいグレーにし、黒い指当て部分と区別して傾きを見やすくしている。

ジャイロ送出中は、同じ入力源の **ボタン押下とスティック位置** も表示する。ボタンは沈んで青く強調され、スティックは倒した方向へ傾く。スティックの押し込みにも対応する。プロコンは左右両方、Joy-Con は選んだ側にある操作部だけが動く。ABXY、十字キー、L/R、ZL/ZR、＋/−、HOME、CAPTURE を、読み取り口が報告する範囲で反映する。SL/SR の可動部もあるが、現行の読み取り口は SL/SR の押下を通知しないため反応しない。

操作の表示は物理パッドの状態であり、マクロ・キー割当・送出側の遊び設定を適用した結果ではない。HID 直結は共有リーダーの最新レポート、パッド API はセンサーを開いたハンドルから読み、別のパッドを開き直すことはない。切断時は中立へ戻す。`.pgyro` 再生や診断用の波形にはボタン情報がないため、操作部は中立のままになる。

描画には pygame と moderngl（OpenGL 3.3 以上）を使い、別プロセスで動かす。更新後は `uv sync` で依存関係を同期する。GPU の滑らかな陰影と材質別の反射を使うため、対応するグラフィックスドライバーが必要である。外部モデルのダウンロードや実行時のネット接続は不要であり、OpenGL を初期化できない場合はログへ理由を表示してプレビューだけを停止する。姿勢はサンプルごとに計算し、描画には最新の姿勢だけを渡すため、描画待ちで送出を待たせない。

実装は `pokecon/domain/imu_orientation.py`（姿勢計算）、`pokecon/ui/imu_preview.py`（窓とプロセス）、`pokecon/ui/controller_mesh.py`（形状）、`pokecon/ui/imu_preview_gpu.py`（GPU 描画）に分かれる。姿勢表示の先例として [JoyCon-Driver の Gyro Window](https://github.com/fossephate/JoyCon-Driver) を確認したが、コードやモデルの流用はしていない。

## ジャイロの記録と再生（.pgyro）

実コントローラーの動きを記録し、後から同じ動きを Switch へ送り直せる。UI は IMU パネル（`SerialController/pokecon/ui/ImuPanel.py`）であり、記録器・再生器の実体は Tk 非依存の [`pokecon/domain/motion_track.py`](../SerialController/pokecon/domain/motion_track.py) である。

- **記録**: 入力源（パッドAPI / HID直結 / マウス）で送出中に「送出値を記録する」を有効にすると、停止までのあいだ **送出前に生成・加工した 6 値（ax,ay,az,gx,gy,gz）** を `[IMU] record_path`（既定 `records/motion.pgyro`）へ書く。保存先は「参照…」で選べる。記録の有無は開始時に読み込み、送出中の切替は次回から反映される。HELLO 未確立・hold でサンプルを読まない刻みは記録にも残らない。書き込み失敗は黙って捨て、停止時に件数をログへ出す。記録はシリアル送信より前であるため、Pico やゲームへの到着を証明しない。
- **再生**: 入力源で「記録の再生」を選び、再生ファイルを指定して「開始」を押す。記録済みの値を **そのまま** 送る（符号・感度・不感帯・軸変換は掛けない）。掛けると記録時の加工が二重になり、記録した動きからずれる。送出周期はヘッダーの `period_us`（v1 は 5000µs = 200Hz）であり、送り切ると自動で停止する（最後の値を送り続けない）。
- 記録先と再生元に同じファイルを指定した場合、再生はそのままだが記録はしない（上書きで元の記録が消えるため）。記録先が空のまま記録を有効にすると開始しない。
- 記録は送出ループの刻みごとに 1 件書き、遅れは詰めて並べる（ファイル上は 5ms 等間隔）。送出が数 tick 遅れたぶんは、記録の長さも実時間より短くなる。

形式（v1、リトルエンディアン）:

| 位置 | 内容 |
|---|---|
| 0-3 | magic `PGYR` |
| 4-5 | version = 1 |
| 6-7 | header_size = 32 |
| 8-11 | period_us = 5000 |
| 12-15 | sample_count |
| 16-19 | flags = 0 |
| 20-27 | start_offset_us（ボタン記録との同期用。単体では0） |
| 28-31 | reserved = 0 |
| 32- | sample_count × 12B（int16-LE ×6） |

- 記録が元の入力そのものではない点に注意する必要がある。SDL センサーは開いた時点でバイアス（`[IMU] gyro_bias`）を引き、`watched()` が符号・`gyro_scale`・不感帯を掛けた後の値が記録対象となる。**同じ記録を別の設定で再生しても、記録時の設定で送った値が出る**ため、記録を撮り直すときは設定を固定する。
- ヘッドレスで試すときは `tools/probes/imu_send.py --record out.pgyro` / `--play out.pgyro`（`--wave sensor` / `--wave hid` と組み合わせる）を使う。

## Blockly の記録との連携

Blockly エディタの「● 記録」は、ジャイロ送出中なら送った IMU サンプルも同時に残す（`pokecon/runtime/blockly_record.py` の聞き手 → `Commands/PythonCommands/blockly_*.pgyro`）。停止時に「ジャイロを再生」ブロックが手順の先頭へ入り、生成コードは `self.gyro_play("<パス>")` を呼ぶ。再生は `OperateMixin.gyro_play` が `transport.start_imu_loop(..., replace=True)` で開始し、コマンド終了時の `_cleanup` が止める。記録値は加工しない（符号・倍率・不感帯を掛け直さない）。詳細は [`docs/BLOCKLY_EDITOR.md`](BLOCKLY_EDITOR.md) の「操作の記録」を参照する。

- IMU 送出ループの持ち主は `start_imu_loop(..., owner=...)` で区別する（`panel` / `macro:<id>`）。`stop_imu_loop(owner=...)` は一致するときだけ止め、省略時（`close` など）は問わずに止める。パネルとマクロの相互乗っ取りについては [`docs/BLOCKLY_EDITOR.md`](BLOCKLY_EDITOR.md) の「ジャイロの競合と持ち主」を参照する。
