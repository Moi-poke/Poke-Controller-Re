# IMU（ジャイロ）経路

`AGENTS.md` から分離したサブシステム固有の注意。IMU・HID・ジャイロ・0x30/0x40 に触るときだけ読む。

- PC→Pico は `T_IMU_SAMPLE`（0x04/LEN12、ax,ay,az,gx,gy,gz の6×int16-LE）を通常5ms間隔で送る。0x30は5ms間隔の3スロットを持ち、送出周期は**15ms**（これより速い反復は過積分の恐れがある）。Picoは0x30生成までに届いた試料を消費し、3件ならそのまま古い順、4件以上なら古い分のジャイロ角度を先頭スロットへ合算する。届いた試料がなければジャイロ0、加速度は最新姿勢を保持する。Picoへ反映するには更新した `Switch-bcon` ファームウェアが必要。
- **0x40の引数はIMU形式の選択**（実測: FW 4.51→`02`=圧縮クォータニオン、3.72→`01`=RAW）。FWは引数を`imu_mode`として保持し、1ならRAW 36B、2なら NS-LIB-HID `ns_mode_2_s` 同形の36B（accel y,x,z＋最大成分基準の30bitクォータニオン＋11bit ms）を返す。`3`は未解明として仮定しない。**現行の実機検証は 3.72＋RAW**（Mario Tennis / Splatoonで確認）。4.51を名乗る場合はmode2のクォータニオン経路が必須。
- 有線0x30のIMUは既定でrole0のみ（`usb_imu_wired_role_ok`）。role1/2で有線ジャイロを試す診断は `JOY_WIRED_IMU_ALL=1`。FW版のA/Bは `JOY_USB_FW_JOY_OLD=1`（Joy役を3.72に）。
- role2の軸写像はFW側で固定（`k_joy_negate_axis`: 加速度・ジャイロともY,Z反転）。SPI校正値の回転だけ `JOY_SPI_CAL_ROT`（0=なし/1=YZ/4=XZ）で切り分けられる。PC側 `[IMU] accel_*/gyro_axes・signs` は恒等が前提（HID直結でも適用される）。
- `[IMU] gyro_dead_dps` は送出直前のジャイロ各軸に効く（`core.imu_wave.apply_gyro_deadband`）。既定0（無効）で小さい動きを残す。必要なら1〜3程度を入れる。`gyro_scale` は実測用トリム。**加工後の値を返さないと不感帯が送出に効かない**（過去に実際に踏んだ）。
- HIDリーダー (`core.nintendo_hid`) はプロセス共有・読み取り専用スレッドが最新0x30を保持する。`ImuPanel` は停止時に共有ハンドルを閉じない。読取失敗が続いたら自分で閉じ、パッド/IMU側が再オープンする（UF2書き込みでUSBが再列挙されるため必須）。
- IMUパネルの入力源は通常 **「パッドAPI」（SDL）／「HID直結」／「マウス」**（Windowsのみ）。`sine`/`step`/`rest`/`manual`、反転・感度・詳細表示は**デバッグ**時だけ出す。ボタンは「開始/停止」。

## マウスでジャイロ

IMUパネルの入力源「マウス」で、PCのマウス移動をジャイロとして送る。
WindowsのRaw Input（`WM_INPUT`、`RIDEV_INPUTSINK`）を使うため、
ポインタ加速や画面端の影響を受けない生の移動量（count）で動く。
Windows以外では入力源の候補に出さず、設定に `mouse` が残っていても
`パッドAPI` へ寄せる。送り先はBCONの `T_IMU_SAMPLE` 経路
（`switch-bcon` / `switch-bcon-proc`）で、入力は既定5ms刻み、Switchへの0x30報告は約15ms刻み。

- **設定欄**: 「ジャイロ設定」を開くと、入力源の直下にその入力源の操作が
  出る。マウスの感度計算と詳細調整は必要なときだけ開く。記録先の指定は
  「送出値を記録する」にチェックを入れると表示される。

- **開始/停止**: 入力源を「マウス」にして「開始」を押すと、キャプチャと
  送出を同時に始める。「停止」で両方止める。
- **解除**: キャプチャ中はカーソルを非表示にし、PokeConのクライアント
  領域へ閉じ込める。解除はグローバルホットキー（既定 `Ctrl+Alt+M`）か
  「停止」。PokeConが前面から外れたときも自動で解除する（クリップも外れる）。
  ホットキーで解除しても送出は続き、ジャイロは0（静止）を送る。
  再度ホットキーを押すと、PokeConが前面にある場合だけ再開する。
- **GUIロックとEsc**: キャプチャ中はTkのマウスイベントを全ウィジェットで
  止めるため、GUIのボタンや仮想パッドを誤クリックしない。停止は **Esc**
  （「停止」ボタンと同じ。送出中の入力源なら種類を問わない）。キャプチャ中は
  入力欄などがEscを消費しても停止を優先する。EscはPokeConのメイン窓と
  ジャイロ欄の窓だけで受け、グローバルホットキーにはしない。開始・解除の
  たびに、仮想パッドとカメラ面で掴んでいたマウススティック／ボタンを
  解放する（再開後にマウス操作が入力を上書きしない）。
- **仮想姿勢と3軸**: マウスXは**ワールドの鉛直軸まわり**（水平に振り向く）、
  マウスYは**機体の横軸まわり**（上下を向く）として、ホスト側の目標姿勢
  `q_target` を更新する。生成済みrawを積分した姿勢 `q_output` との差分
  `q_output^-1 * q_target` を機体座標の回転ベクトルへ直し、5msあたりの
  3軸rawへ量子化する。ピッチを付けた状態でヨーを振ると機体X（ロール）
  にも成分が出る。加速度は `q_output^-1 * 静止重力`。`q_output` は
  ゲームの実測姿勢ではなく、送出生成値から計算したホスト側の姿勢。
  ファームウェアへのコマンドは既存の6値送信のまま。
- **角度の保存**: ホストの量子化端数は次のサンプルへ繰り越す。
  差分が `mouse_backlog_deg`（既定30°）を超える速いフリックは超過分を捨てる。
  Picoでは0x30間に3件を超える試料を受けた場合、古いジャイロ値を
  先頭スロットへ合算し、最新の加速度を使う。ただし3枠の表現範囲を超える
  合算値は飽和し、0x30が100ms以上止まれば古い動きは捨てる。
- **軸・符号**: `mouse_yaw_axis` は**ワールドの鉛直軸**（既定Z）、
  `mouse_pitch_axis` は**機体の横軸**（既定Y）。右への移動が右向きの
  ヨー、下への移動が下向きのピッチになる符号を既定にしている。実機の
  向きが違う場合は画面の「左右反転」「上下反転」で直す。軸・符号の
  上書きは `mouse_yaw_axis` / `mouse_pitch_axis`（0..2）と
  `mouse_yaw_sign` / `mouse_pitch_sign`（+1/-1）。
- **ピッチ上限**: `mouse_pitch_limit_deg`（既定89°）。真上・真下付近で
  ヨー軸が定まらなくなるのを避ける。超える入力はそこで止まる。
- **ロール**: 画面の「ロール」で `none` / `右ボタン` / `Shift` を選ぶ。
  修飾中はマウスXがワールドヨーではなく機体のロール軸
  （`mouse_roll_axis`、既定X）まわりになる。`mouse_roll_sign` で向きを
  反転。右ボタンはキャプチャ中GUIクリックを止めているので競合しない。
  設定は次のWM_INPUTから効く。
- **姿勢リセット**: 既定 `Ctrl+Alt+R`（`mouse_reset_hotkey`）または
  画面の「姿勢リセット」で、仮想姿勢を水平・正面へ戻す。マウスでは
  手を元の位置へ戻す自然な復帰ができないため、ピッチ・ロールがずれた
  ときはゲーム側のリセンターと併用する。リセット直後はジャイロ0・
  静止重力を送る。
- **感度**: `mouse_sensitivity` [deg/count]（画面の「感度」）。`mouse_ratio_y`
  は上下の比。マウスのDPIを変えたら感度を測り直す。`gyro_scale` は
  デバッグ時に表示する「送出倍率」で、送出直前の倍率。`gyro_dead_dps` は
  マウス源では適用しない（遅いエイムが止まるため）。
- **感度の逆算**: 「感度を距離から計算」を開き、「DPI」と「360°距離」に
  マウスのDPIと目標距離（例20cm）を入れ、「計算」を押すと
  `感度 = 360×2.54 / (DPI×cm)` で設定する。下の「現在 xxcm/360°」は
  今の感度での実距離。Raw InputのcountはDPIそのもので、Windowsの
  ポインタ速度・加速は乗らない。
  DPIはマウス付属ソフトの設定値を使う（DPIが不明なら、近い値を入れて
  「現在」の表示と実際のマウス移動距離を突き合わせて補正する）。
  `mouse_dpi` / `mouse_cm_per_360` はiniにも保存される。
- **平滑化**: `mouse_smoothing`（0.05..1.0、既定1.0）。画面の
  「詳細調整」内にある。小さくするとパルスは広がるが、操作遅延が増える。
  遅延が気になる場合はまず1.0のまま送達経路を調べる。
- **周期**: `mouse_interval_ms`（1..20、既定5）。0x30の5ms×3に合わせ、
  通常は5のまま使う。異なる周期では1サンプルの角度の解釈がずれる。
  画面の感度・上下比・平滑化・反転は確定（フォーカスを外す / Enter）で
  保存し、送出中なら次のサンプルから効く。ロール修飾は次のWM_INPUTから。
  解除・リセットのホットキー変更は次の開始から。
- **プロトコル**: 新しいコマンドは足さず、既存の `T_IMU_SAMPLE`
  （BCONフレームのseq・チェックサム）をそのまま使う。計画書の
  「角度増分コマンド」は現行構成では不要。
- **ジャイロ係数**: `mouse_deg_per_lsb`（既定0.06103）。SPI較正値や実機
  ダンプで係数が違う場合の上書き口。
- **ポーリングレート**: 送出中の統計行 `入力=NNN/s` が、実際に受け取っている
  Raw Inputのイベントレート（マウスを動かしている間）。停止中に単体で測る
  ときは `uv run --frozen python tools/probes/mouse_rate.py --seconds 5`。
- **生波形の階段**: 1カウントは `感度 / (0.06103×0.005)` raw。
  感度0.0381なら約125rawの5msパルスになる。整数カウントによる
  ギザギザは波形の見た目だけでは遅延の証拠にならない。同じcm/360°のまま
  DPIを上げると1カウントの角度は細かくなる（感度も同じ比率で下げる）。
  ただしゲーム側の不感帯が不明なままDPIや平滑化を変えても、
  微動の反映が改善するとは限らない。
- **重力追従**: 画面の「詳細調整」にある。既定は `q_output` から毎サンプル
  重力を計算する。ゲームが重力でピッチを水平へ戻す場合も、仮想コントローラー
  が実際に傾いた状態と一致する。`mouse_gravity_follow=0` で固定重力に
  戻せる（比較用）。
- **対象外**: 振る動作（加速度の急変）はマウス移動からは作らない。必要なら
  実機ダンプの加速度・ジャイロ波形を数十ms流す別機能にする。

未検証（実機が必要）: 軸の割り当てと符号、ロールの向き、ピッチ上限、
`mouse_deg_per_lsb` の実機一致、0x30での送達率、ゲーム内の感度・遅延。
ホストは `q_target`/`q_output` の差分からrawへ量子化し、Picoは
**別の段階で**未報告のrawを0x30の3枠へ配分する。古い「最新3件」方式の
ファームウェアには後者の改善がない。

`switch-bcon-proc` は子が詰まったとき、未送出IMUを最大100ms分だけ
保持し、ジャイロ値を合算して送る。超過した古い値や停止・hold中の未送出値は
`imu_stats()["stale"]` に数える。`sent` は親が受理した試料数、
`frames` は子へ投入したフレーム数、`delivered` は子がシリアルへ
書けたと応答したフレーム数であり、Switchへの到着確認ではない。
合算で角度を守っても、停滞中の時間を短い報告へ圧縮するため、
ゲーム内の動きの滑らかさと遅延は実機で比較する。

## 3D ジャイロプレビュー

ジャイロ欄の「3Dプレビュー」で、姿勢を確認する別ウィンドウを開く。
入力源を選んで「開始」を押すと、パネルが送出するサンプルに合わせてモデルが回転する。
送出前でも窓は開けるが、サンプルが届くまでは「待機中」と表示する。
中立姿勢ではボタン面を正面から表示する。固定の斜め視点は使わず、コントローラーを傾けた分だけモデルが傾く。
モデルの背景は明るいグレーにし、黒い筐体の輪郭を見分けやすくしている。

- **モデル切替**: 上部のボタン、または `1` / `2` / `3` キーで、プロコン、Joy-Con (L)、Joy-Con (R) を選ぶ。切替は外観だけで、入力源や送出値は変えない。
- **正面リセット**: ボタンまたは `R` キーを押した時点の持ち方を、新しい正面の基準にする。左右の向きと傾きを含めてボタン面が真正面を向き、その後は基準から動かした分だけ追従する。入力停止中も最後の受信姿勢で即時に反映し、まだ未受信なら最初に届いた姿勢を基準にする。表示だけの補正で、送出値は変えない。
- **終了**: 窓の閉じるボタンか `Esc`。プレビューを閉じても送出は続く。再度「3Dプレビュー」を押せば開き直せる。
- **入力停止**: 0.5 秒以上サンプルが来ないと姿勢を最後の向きで止め、「入力停止」と表示する。ボタンとスティックは中立に戻す。

姿勢は、符号、感度、不感帯などを適用した **パネルの送出値**から計算する。
「記録の再生」でも姿勢を表示できるが、マクロが独自に開始した送出はこの窓の対象外。
ジャイロを積分し、加速度が約 1g のときに傾きを補正する。磁気センサーを使わないため、左右の向きはドリフトする。
モデルは実物を参考にした手続き生成の形状で、スキャンデータではない。
プロコンは mm 単位で定義した筐体形状をメッシュ化し、Joy-Con は外側とレール側で角の丸みを変えている。
グリップ、スティックのくぼみ、ボタンの文字、継ぎ目やレールを描き、文字と可動部は取り付け面に沿って動く。
スティックの球状の根元と軸は明るいグレーにし、黒い指当て部分と区別して傾きを見やすくしている。

ジャイロ送出中は、同じ入力源の **ボタン押下とスティック位置**も表示する。
ボタンは沈んで青く強調され、スティックは倒した方向へ傾く。スティックの押し込みにも対応する。
プロコンは左右両方、Joy-Con は選んだ側にある操作部だけが動く。
ABXY、十字キー、L/R、ZL/ZR、＋/−、HOME、CAPTURE を、読み取り口が報告する範囲で反映する。
SL/SR の可動部もあるが、現行の読み取り口は SL/SR の押下を通知しないため反応しない。

操作の表示は物理パッドの状態で、マクロ・キー割当・送出側の遊び設定を適用した結果ではない。
HID直結は共有リーダーの最新レポート、パッドAPIはセンサーを開いたハンドルから読む。別のパッドを開き直すことはない。
切断時は中立へ戻す。`.pgyro` 再生や診断用の波形にはボタン情報がないため、操作部は中立のままになる。

描画には pygame と moderngl（OpenGL 3.3 以上）を使い、別プロセスで動かす。
更新後は `uv sync` で依存関係を同期する。GPU の滑らかな陰影と材質別の反射を使うため、対応するグラフィックスドライバーが必要。
外部モデルのダウンロードや実行時のネット接続は不要。OpenGL を初期化できない場合は、ログへ理由を表示してプレビューだけを停止する。
姿勢はサンプルごとに計算し、描画には最新の姿勢だけを渡すため、描画待ちで送出を待たせない。
実装は `pokecon/domain/imu_orientation.py`（姿勢計算）、`pokecon/ui/imu_preview.py`（窓とプロセス）、
`pokecon/ui/controller_mesh.py`（形状）、`pokecon/ui/imu_preview_gpu.py`（GPU 描画）。
姿勢表示の先例として [JoyCon-Driver の Gyro Window](https://github.com/fossephate/JoyCon-Driver) を確認した。コードやモデルの流用はしていない。

## ジャイロの記録と再生（.pgyro）

実コントローラーの動きを記録し、後から同じ動きを Switch へ送り直せる。UI は
IMUパネル（`SerialController/pokecon/ui/ImuPanel.py`）で、記録器・再生器の実体は
Tk 非依存の [`pokecon/domain/motion_track.py`](../SerialController/pokecon/domain/motion_track.py)。

- **記録**: 入力源（パッドAPI / HID直結 / マウス）で送出中に
  「送出値を記録する」を有効にすると、停止までのあいだ
  **送出前に生成・加工した6値（ax,ay,az,gx,gy,gz）**を
  `[IMU] record_path`（既定 `records/motion.pgyro`）へ書く。保存先は
  「参照…」で選べる。記録の有無は開始時に読み、送出中の切替は次回から。
  HELLO未確立・holdでサンプルを読まない刻みは記録にも残らない。
  書き込み失敗は黙って捨て、停止時に件数をログへ出す。
  記録はシリアル送信より前なので、Picoやゲームへの到着を証明しない。
- **再生**: 入力源で「記録の再生」を選び、再生ファイルを指定して「開始」。
  記録済みの値を **そのまま**送る（符号・感度・不感帯・軸変換は掛けない）。
  掛けると記録時の加工が二重になり、記録した動きからずれる。送出周期は
  ヘッダーの `period_us`（v1 は 5000µs = 200Hz）で、送り切ると自動で停止する
  （最後の値を送り続けない）。
- 記録先と再生元に同じファイルを指定した場合、再生はそのままだが記録はしない
  （上書きで元の記録が消えるため）。記録先が空のまま記録を有効にすると開始しない。

- 記録は送出ループの刻みごとに1件書き、遅れは詰めて並べる（ファイル上は
  5ms 等間隔）。送出が数tick遅れたぶんは記録の長さも実時間より短くなる。

形式（v1、リトルエンディアン）:

| 位置 | 内容 |
|---|---|
| 0-3 | magic `PGYR` |
| 4-5 | version = 1 |
| 6-7 | header_size = 32 |
| 8-11 | period_us = 5000 |
| 12-15 | sample_count |
| 16-19 | flags = 0 |
| 20-27 | start_offset_us（ボタン記録との同期用。単体では0） |
| 28-31 | reserved = 0 |
| 32- | sample_count × 12B（int16-LE ×6） |

- 記録が元の入力そのものではない点に注意: SDLセンサーは開いた時点でバイアス
  （`[IMU] gyro_bias`）を引き、`watched()` が符号・`gyro_scale`・不感帯を
  掛けた後の値が記録対象。**同じ記録を別の設定で再生しても、記録時の設定で
  送った値が出る**。記録を撮り直すときは設定を固定する。
- ヘッドレスで試すときは `tools/probes/imu_send.py --record out.pgyro` /
  `--play out.pgyro`（`--wave sensor` / `--wave hid` と組み合わせる）。

## Blockly の記録との連携

Blockly エディタの「● 記録」は、ジャイロ送出中なら送った IMU サンプルも同時に
残す（`pokecon/runtime/blockly_record.py` の聞き手 → `Commands/PythonCommands/blockly_*.pgyro`）。
停止時に「ジャイロを再生」ブロックが手順の先頭へ入り、生成コードは
`self.gyro_play("<パス>")` を呼ぶ。再生は `OperateMixin.gyro_play` が
`transport.start_imu_loop(..., replace=True)` で開始し、コマンド終了時の
`_cleanup` が止める。記録値は加工しない（符号・倍率・不感帯を掛け直さない）。
詳細は [`docs/BLOCKLY_EDITOR.md`](BLOCKLY_EDITOR.md) の「操作の記録」。

- IMU 送出ループの持ち主は `start_imu_loop(..., owner=...)` で区別する（`panel` / `macro:<id>`）。
  `stop_imu_loop(owner=...)` は一致するときだけ止め、省略時（`close` など）は問わずに止める。
  パネルとマクロの相互乗っ取りは [`docs/BLOCKLY_EDITOR.md`](BLOCKLY_EDITOR.md) の
  「ジャイロの競合と持ち主」を参照。
